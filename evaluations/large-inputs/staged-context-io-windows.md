# Windowsでの累積原文の展開・照合（#318）

Windows 11・Python 3.13.17。同じ合成入力でウォームアップ1回後に、別プロセスで旧→新→新→旧の順に各1回を計測した。比較時の旧版は `91074035`。新旧いずれもJunie、ビルド、外部チェッカー、PHP/C#の実行は含まない。ファイルを開く回数・論理読込量・Pythonのピーク割当は、経過時間とは別に計測した。

合成入力は日本語・CRLFを含むUTF-8カプセル12区間（各117,159 B）、隣接境界資料12個、固定参考資料8件×512 KiB。1〜12区間を順次展開し、途中を再開扱いにして、毎回移行対象外ファイルの起動前と終了後のハッシュを比較した。

| 計測した値 | 旧 | 新 |
| --- | ---: | ---: |
| カプセル展開時間 | 429.97 / 478.27 ms | 349.65 / 300.03 ms |
| 保存原文を開く回数 | 102 | 78 |
| 保存原文の論理読込量 | 11,950,218 B | 9,138,402 B |
| 計測内のSHA-256計算回数 | 564 | 552 |
| Pythonのピーク割当 | 671,485 B | 672,071 B |

最終出力の指紋は4回とも一致。現在区間のSHA-256が固定版と一致する場合だけ、照合したバイトを同じ区間内で使う。1 MiBを超える場合は、従来のストリーミング照合とコピーを使う。過去区間・参考資料の照合や、Junie起動後に展開先が書き換わっていないかの照合は維持する。起動間や再開時に使い回すキャッシュはない。

回帰では、元の出典順・本文、手修正、再開、同サイズの原文変更の拒否を確認した。別の合成試験では、同サイズ・同時刻に差し替えた原文および参考資料を拒否し、参考資料を改めて固定したときだけ反映することも確認した。

経過時間は展開工程だけの値で、実運用の全体時間やトークン削減を示さない。過去区間の照合は従来どおり残る。

#329マージ後の `64197db` を基準にした追加の新旧1回比較では、出力の指紋は同一、展開時間は 519.89→313.93 ms。30・70・110 ms後に停止を要求する別計測では、両版とも3回すべて中断し、応答時間は旧64–190 ms、新74–103 msだった。短い追試のため、この差を停止性能の改善とはみなさない。
