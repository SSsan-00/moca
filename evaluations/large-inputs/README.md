# 2万行・資料200件の実Junie検証

2026-11-17、macOS、Junie 26.11.1（4020.10、Junie Lite）、.NET SDK 10.0.201、ローカルPHPで検証。通常のダッシュボードから起動し、ACPのモデル不足に対して画面の「今回のみ非対話モードで再試行」を選び、実際のJunie `--task` を使った。セッションに記録されたモデルは `Qwen/Qwen3.6-27B-FP8`。

## 入力と検証範囲

- PHPは20,000行・1,024,391バイト。19,979件のリテラル代入と21行の関数・条件分岐などからなる合成ケース。当時の既定値500,000文字で3カプセルに分割した。現行の既定値とは別で、再現用設定は500,000文字を明示する。
- 資料200件・1,531,171バイト。必須事項2件と詳細198件で、そのうち5件が該当する。末尾だけに現れる空配列の条件も選別対象に含める。
- 文字列に重複、日本語、絵文字、引用符、アポストロフィ、バックスラッシュ、文字としての `\n` を含める。値はハッシュから作り、先頭や末尾のサンプリングでは全件を復元できない。
- 移行前に元PHPを実行し、`all`・`reverse`・`selected`・`empty`・`unknown` の期待結果を固定する。`after_build` はビルド済みC#を実行し、全要素の値と順序を比較する。件数だけの検査ではない。
- 独自チェッカーは6個の規約定数と隣接ヘルパー2個の利用を検査する。移行後に `PolicyVersion` を意図的に壊し、Junieの自動修正と再ビルド・再テスト・再チェックも試す。

## 発見と変更

1. 資料の準備で、既に読んだ全資料の文字数を毎行数え直していた。ファイル単位の処理に変更した。カプセル、全資料のハッシュ、行範囲は変更前と完全に一致する。
2. 大量の資料を選別したあと、Junieが要求されたJSONの代わりに説明文を返し、移行前に停止した。長い入力では判定JSONをファイルに保存させ、完了トークンと全件のID・適用可否・理由を検証する。索引とファイルの収録範囲が64,000 UTF-8バイト以内なら一覧を起動時に供給する。上限超過時も切り捨てず全文のファイル参照を使う。
3. 区切りごとに現在の原文しか参照できない状態では、後続区間で先頭8,321件が消えた。処理済みの原文を順番に残し、累積結果と照合させる。参照用の境界行を追加しないこと、PHPの単一引用符内のエスケープ規則も明示する。
4. 全件の値が一致しても、`selected` が誤って `substring` と実装された。最終区間で条件式・比較文字列・演算子・処理順・戻り値を原文と再確認させ、先行区間の仮実装も修正する。
5. 生成されたC#は512 KiBを超えるため、進捗エディタの上限をビルド確認画面と同じ8 MiBに揃えた。超過時は外部エディタを案内する。

検証失敗は成功扱いにしていない。資料選別の失敗は `junie_failed`、値の欠落と条件の誤りは `script_failed` で停止し、その時点ではチェッカーへ進まなかった。チェックや期待値を緩めず、同一のPHP・資料・5条件のテストで再試行した。

最終Runは `de636f53-2baf-4522-84c3-5fdcbfbb997c`。全体の経過時間は592.252秒（約9分52秒）。198件の詳細判定が保存され、期待する5件を選択した。3カプセルを移行後、5条件の全件比較が成功。意図的に壊した規約定数をチェッカーが検出し、Junieが1回で修正した。同じRunで再ビルドと5条件の全件比較が再び成功し、チェッカー終了コードも0になった。人による移行先の修正や追加プロンプトは与えていない。

Junie処理時間は、Run IDで対応するセッションの `TaskStartedEvent` から最後の完全なイベントまでの時間を合算したもの。起動・ACPの再試行確認・ビルドなどは含まない。ツール操作数は `ToolBlockUpdatedEvent` の異なる `stepId` 数。入力合計はキャッシュ読み込みを含み、課金額ではない。工程別の内訳、Run ID、入力ハッシュは[計測データ](results.json)に記録した。監視スクリプトが準備用Runを誤って拾い途中停止した1試行は、結果から除外している。

## 準備処理の計測

各版1回のウォームアップ後に5回計測。計測プロファイラなしの中央値は、変更前 `2505f46` の1.455秒から0.423秒へ約71%減った。全試行で入力内容・カプセル分割・資料のハッシュと行範囲が一致した。最大RSSはこの準備プロセスで約37 MBと39 MBだった。ブラウザー、.NET、Junieを含む全体のメモリー量ではない。

実Junieの移行全体はモデル応答と修正回数に左右される。変更前は資料選別で停止したため、同じ成功条件を満たす実行同士の速度比較にはならない。準備処理の短縮率を移行全体の短縮率とは扱わない。

## ダッシュボードと回帰検証

ChromeとPlaywrightで1,150,341バイトのC#、20,000行のPHPを実際の画面で開いた。幅390・768・1440pxでページ全体の横はみ出しがなく、日本語とキーボードのフォーカス表示を確認した。JavaScriptエラーはなかった。コード本文内の横スクロールは通常どおり利用できる。

回帰テストには、200資料の全文と行範囲の保持、長い索引の全文参照、未判定・不正な型・空の理由・別トークンの拒否、累積原文の復元と未来の区間の除外、最終区間だけの振り返り、512 KiB超の手修正と追加指示の反映、8 MiBの境界、CRLF/BOM保持を含む。

ローカル回帰テストは239件中237件成功・環境条件による2件スキップ。最終区間の指示変更後は、該当する15件も再実行して確認した。

## 再現

Python環境にハーネスを導入し、Junie、.NET SDK 10、PHPが利用できる状態で実行する。PHPは検証用の正解生成にのみ必要で、ハーネス本体の追加依存ではない。

```sh
python evaluations/large-inputs/create_fixture.py
php-to-csharp-harness run --config <表示されたフォルダ>/harness.toml --unit large-catalog --dashboard
```

生成・編集は新しい一時Gitリポジトリとそのworktreeに限定する。通常のAPIやデータベースに依存する実業務の2万行、200件すべてが必須の巨大ルール、Windows実機でのモデル実行は今回の検証範囲外。AIへの照合指示だけでは正しさを保証できないため、対象業務に合わせた独立したテストとチェッカーが必要。
