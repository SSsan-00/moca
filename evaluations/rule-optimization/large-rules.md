# 大量ルールを整理するスキルの改善

2026-11-17、macOS、Junie 26.11.1（4020.10、Junie Lite）で実施。スキルとその補助ツールを変更し、移行処理のPythonコードは比較時の `5a31852` に固定した。別ワークスペースの実装変更とは分けて計測した。

## 入力と確認方法

[前回成功した2万行ケース](../rule-loading/large-php.md)と同じPHP、期待値、ヘルパー、チェッカー、故障注入フックを使用した。スキルの入力では、以前DB詳細の末尾から取り出した全体向け義務T90を、同じ分割前の原文へ戻して再整理する。ルール情報は追加・削除せず、移行先名を含まない注文詳細も維持した。

入力は13文書・37ページ。設定のバックアップ、全ページの引用・意味確認・必須行、分割前後の全行対応、原文のハッシュ、対象外設定の一致を外から検証した。整理後は必須2件・詳細12件となり、T90は必須側に残った。設定確認のための準備・移行・フック実行はない。

Junieの対話画面から `/harness-optimize-rules` を明示して同じ依頼を送り、スキルの読込イベントも確認した。途中の修正指示は追加していない。

## 変更した内容

- 最大2ページを表示し、引用・意味・必須行を確認して記録してから次へ進む。`record --next` が記録の検証・保存と次ページの取得をまとめる。未記録や引用違いがあれば進めず、以前のページの再読はできる。
- 既存設定では `start` が保存したバックアップと棚卸しを再利用する。新規登録専用の手順は別資料へ分離した。
- 新しいAgentは、起動時に提供済みの原文と索引だけの資料を区別する。同じ本文を確認済みの記録のためだけに取得し直させず、適用条件・例外と結果の照合は維持する。
- 参照資料・付属ヘルパーは読み取り専用と明記し、独自の抽出・照合処理や中間データは `.migration-scratch/` に置く。
- `plan.json` の `format_version: 2` で新しい案内を生成する。省略・1の既存PACKは従来と同じバイト列で検証でき、原文や生成物を上書きしない。

## スキル単体の実測

両方を200ステップにそろえ、全ページの確認、分割、設定反映、結果報告まで完了した試行を比較する。時間はJunieのタスク開始から最終イベントまで。起動・信頼確認待ちは含まない。入力合計にはキャッシュを含み、キャッシュ作成は全試行0。

| 指標 | 旧スキル | 最終版 |
| --- | ---: | ---: |
| Junie時間（秒） | 321.609 | 163.744 |
| 入力合計 | 3,543,602 | 2,669,474 |
| 通常入力 | 211,922 | 207,986 |
| キャッシュ読み込み | 3,331,680 | 2,461,488 |
| 出力 | 18,191 | 14,830 |
| 結果 | 全行検証・設定反映済み | 全行検証・設定反映済み |

この一組では時間が49.1%、入力合計が24.7%、通常入力が1.9%、出力が18.5%減った。原文の末尾にあった全体義務を必須へ戻し、索引と読み方の案内を加えるため、必須本文自体は608文字から1,488文字へ増えている。

旧スキルの完了試行は中間版と並行、最終版は単独で実行した。時間にはこの実行負荷やサービス応答の違いも含まれるため、差のすべてを変更の効果とは断定しない。料金や別案件の削減率を保証する比較でもない。

## 移行時に見つかった問題

最初の移行試行 `b91c5554-5858-4824-ac8b-3ee21481532d` は、Junieが `.migration-materials/php_literals.py` を独自実装に書き換えたため、既存の対象外変更検査で停止した。カプセル1の変更はworktreeへ反映されず、ビルド・自動修正には進んでいない。生成するAgentに参照資料と付属ヘルパーの読み取り専用扱い、一時処理の配置先を明記した。実行処理の検査は緩めていない。

この未完了試行はJunie時間127.522秒、入力合計1,415,017、出力16,970。成功した前回Runより速いという比較には使わない。

## 2万行の移行・自動修正の実測

補強後のスキルを同じ原文へ再実行し、生成した設定で新しいRun `1fc4ccbe-bb69-4f57-a5c2-a4ef2b9cdd9a` を作成した。前回の成功Run `f92498d6-7199-439a-b375-3796ba5a0efc` と比較する。モデルはともに `Qwen/Qwen3.6-27B-FP8`、カプセル上限500,000文字、2カプセル。途中の修正指示や移行先の手編集は加えていない。

| 指標 | 前回の成功Run | 今回 |
| --- | ---: | ---: |
| Junie時間（秒） | 314.394 | 221.063 |
| 入力合計 | 3,852,213 | 3,290,459 |
| 通常入力 | 341,253 | 326,683 |
| キャッシュ読み込み | 3,510,960 | 2,963,776 |
| キャッシュ作成 | 0 | 0 |
| 出力 | 32,337 | 21,621 |

Junie時間は29.7%、入力合計は14.6%、出力は33.1%減った。スキルで原文を整理する一度限りの時間・使用量は、この表には加算していない。

| 工程 | 前回 秒 / 入力合計 | 今回 秒 / 入力合計 |
| --- | ---: | ---: |
| 詳細の事前確認 | 72.379 / 770,173 | 57.782 / 646,587 |
| カプセル1 | 70.620 / 810,406 | 54.294 / 643,340 |
| カプセル2 | 157.949 / 2,173,565 | 93.480 / 1,901,479 |
| 自動修正 | 13.446 / 98,069 | 15.507 / 99,053 |

全工程が短縮したわけではない。カプセル2の原文抽出ヘルパー関連の呼出しは8回から2回へ減った一方、カプセル1では提供済みルール3件のファイル再読が残った。スキルの案内だけで重複取得を完全に解消できたという結果ではなく、Junieの実行経路のばらつきも含む一組の比較である。

精度はJunieの報告だけでなく、以下で確認した。

- **自動修正前**にビルドとチェッカーが成功。全19,997件の値・順序・重複・特殊文字、10項目のルール定数、注文詳細、DB資料の末尾にあったT90、隣接する2つの共通ヘルパーを確認した。
- 選択された詳細は注文用1件のみ。無関係な11件は、移行用フォルダにも起動時の本文にもなく、移行・修正セッションでの参照もなかった。
- 初回の検証成功後、同じフックが3定数を故障注入。自動修正1回で回復し、再ビルドとチェッカーが成功した。
- 保存した初回・修正後のソースを別フォルダで再ビルド・実行し、全19,997件の不一致0件。2つのヘルパーを変更した別実行でも、全件へ変更が反映された。
- スキル実行前後で元PHP・期待値・ルール原文・チェッカー・フック・ヘルパーを照合。ルール分割後の全行対応と、ルール以外の設定の保持も確認した。生成案内の文字数が変わるため、カプセル境界まで同じバイト列であるとは扱っていない。

固定ケースでの確認であり、未知のルールの意味理解や全案件での速度を保証するものではない。失敗試行、セッションID、工程別の使用量、原文と生成物のハッシュ、独立した実行結果は [実測JSON](large-rules-results.json) に残した。

## 再現方法

保存済み2万行ケースを複製し、比較対象のスキルと補助ツールを置く。

```text
python evaluations/rule-optimization/create_large_fixture.py <前回の2万行ケース保存先> --tools-from <比較するハーネスのチェックアウト>
```

出力されたフォルダの `harness/` で `junie --brave --model mix.lite --max-steps 200` を起動し、対話画面から次を送る。ハーネスをインストールしたPythonを使える環境で行う。

```text
/harness-optimize-rules harness.local.toml のプロジェクト共通の移行ルールの読み込み方を最適化して、設定へ反映してください。作業領域は rule-workspace/Benchmark です。必須事項を残し、必要時に読む詳細には読む場面を設定してください。原文と対象外の設定は保持し、移行は実行しないでください。完了したら作業領域の loading-review.md に変更内容と判断理由、必須本文の文字数の前後を記録してください。
```

移行後の保存済みRunは [analyze_large_runs.py](../rule-loading/analyze_large_runs.py) と [verify_large_targets.py](../rule-loading/verify_large_targets.py) で、資料の選択・初回適用・使用量・実行結果を再照合した。
