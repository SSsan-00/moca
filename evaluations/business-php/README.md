# 業務PHP 2,000行・資料200件の静的移行検証

条件分岐・関数呼び出し・DBアクセスを含む合成PHPを、通常のダッシュボードから実Junieで移行する。検証時間を抑えるため、入力を20,000行から**2,000行**へ縮小した。移行元を実行できることは前提にしない。

移行元PHP、生成した業務コード、DBは実行しない。C#をライブラリとしてビルドし、静的チェッカーで原文との対応を調べる。アプリを実行するランナー、初期DB、実行結果の比較はこの検証に含めない。

## 入力と確認範囲

- PHPは物理2,000行。注文・在庫・入金・取消・返金・集計と、16契約の料金計算を含む24関数。契約には割引、クーポン、送料、税、与信の分岐がある。
- 資料200件は、必須2件・関連する詳細10件・無関係188件。関連資料をすべて選び、無関係な資料を除外したことも確認する。
- 移行対象は `BusinessService.cs` と `PolicyCatalog.cs`。提供するC#は公開リクエスト型、契約値を保持する型、未実装の対象ファイルだけ。業務処理と契約値の抽出はJunieが行う。
- C#ビルドで構文・型・APIの整合を確認する。実行エントリーポイントは設けない。
- 静的チェッカーはSDK付属のRoslynでC#のソースを解析する。移行先アセンブリをロードせず、業務メソッドも呼び出さない。
- 契約16件・416項目の定数を型と値で照合し、SQL17種類の構造、拒否コード21種類を照合する。SQLは空白・キーワードの大小・パラメーター名の変更を許容し、パラメーターの再利用関係を保持する。
- 明らかな `object` → `int` の直接アンボックス、トランザクション戻り値の破棄を検出する。パラメーター化、`DBNull.Value`、コマンドへのトランザクション設定の記述も確認する。

これは固定した合成入力向けのチェッカーであり、一般のPHP/C#の意味的同値性を証明するものではない。SQLの書き換えを伴う等価な実装は指摘になる場合がある。定数やエラー文字列の存在だけでは、すべての分岐から正しく参照される保証にはならない。生成後の共通処理も原文と読み比べるが、実行時のDB動作、全経路の正しさ、同時更新、処理性能は未検証とする。

## 今回の改善

1. 曖昧な資料を説明だけで除外しないようにした。事前判定にハッシュを照合済みの詳細本文を配置し、必要な本文を読んで判断できる。
2. Junieの子プロセスに `PYTHONDONTWRITEBYTECODE=1` を渡す。補助Pythonのimportによる `__pycache__` が、読み取り専用資料の変更として誤停止する問題を防ぐ。
3. PHPの復号済み文字列・真偽値・null・64ビット整数をC#のリテラルへ変換する小さな補助を追加した。PythonやPHPの引用符・真偽値表記の混入を避ける。
4. 分割された関数は元の行順で結合して解析し、正しい抽出スクリプトを再利用するよう指示した。SQLのバインド、null、トランザクション、最終的な全定数の照合も指示する。
5. 資料選別・移行・追加指示・自動修正の各段階で、ソースを静的に確認し、業務コードやDBを実行しない方針を明記した。ハーネスに利用者が設定したビルド・チェッカー・追加スクリプトの動作は別に扱う。

## 測定と再実行

ダッシュボード起動直前からチェッカー完了と画面反映までを測る。資料選別、移行、自動修正、ビルド、静的チェック、信頼確認等の待ち時間を含む。データ生成と初回のNuGet取得は事前に済ませる。単発の結果から一般的な高速化率は算出しない。

.NET SDK 10、Git、認証済みJunie CLI、ハーネスのPython依存が必要。PHPやDBサーバーのインストールは不要。画面の自動操作にはPlaywrightとChromeを使用する。ビルドは `Microsoft.Data.Sqlite.Core 10.0.13` のAPI参照のみで、SQLiteのネイティブエンジンを配置しない。

```sh
python evaluations/business-php/create_fixture.py
# 表示された検証用ディレクトリを指定する。
PYTHONPATH=/absolute/path/to/harness/src python evaluations/business-php/run_dashboard.py /path/to/fixture /path/to/results
python evaluations/business-php/collect.py /path/to/results/result.json > results.json
```

作成される `app` は独立したGitリポジトリ。Runと作業ツリーはその外の `runs`・`trees` に保存する。ACPでモデルが取得できない環境では、通常画面の「今回のみ非対話モードで再試行」から実際の `--task` に切り替える。

検証器の自己確認として、未実装の移行先は不合格になること、定数の取り違え・欠落・重複・SQL欠落等を検出することを確認する。Roslynの定数抽出は、名前付き引数・型推論・定数式・Unicode・64ビット整数と、不適切なアンボックスの検出を確認する。

以前の20,000行での実行比較試行は完了条件に達していない。今回とは入力規模と判定方法が異なるため、速度・精度の比較対象にしない。
