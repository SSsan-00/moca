# 大量ルールと2万行PHPの実Junie検証

2026-11-17、macOS、Junie 26.11.1（4020.10、Junie Lite）、.NET SDK 10.0.201で実施。途中でJunieへ修正指示を追加せず、プロジェクトの信頼確認だけを操作した。

## 固定した入力と検証方法

[前回](detail-review.md)の14ルールをバイト単位で保持し、PHPを20,000行へ拡張した。必須2件・詳細12件、注文詳細には移行先のクラス名・メソッド名を含めていない。共通のT90ルールは、以前のスキル検証でDB詳細の末尾から必須事項へ移したものをそのまま使った。

PHPは配列の初期化、19,997件のリテラル追加、JSON出力で構成する。単なるコメントの水増しではない。値・順序・重複に加え、引用符、バックスラッシュ、日本語、カプセル境界付近の例外を含む。PHP自体を実行し、期待値との一致も確認した。ただし、大規模な実業務リポジトリや複雑な制御構造を網羅するケースではない。

文字数上限500,000で2カプセル（499,975文字・440,213文字）になり、元の行範囲は1〜10,639行、10,640〜20,000行。ルール原文のハッシュ、カプセルのハッシュは全試行で同一。ルールの配置先名を短くしたため、出典を含む保存本文は前回の74,369文字から74,110文字へ変わるが、ルール原文は変えていない。

移行後フックは、**自動修正前**のソースを保存し、ビルドと実行結果を検査する。全件一致、10個の定数、同フォルダと隣のincのヘルパー参照が合格した場合だけ、R4・ORD・T90の3定数を意図的に壊す。初回に不具合があれば故障は追加せず、その不具合を通常の自動修正へ渡す。

## 見つかった問題と修正

- 最初の試行では、後半カプセルで配列要素のカンマが欠落し、特殊文字も二重エスケープされた。PHPの文字列を解釈してから移行先向けに一度だけエンコードし、配列全体と接続部分を検証する指示を追加した。
- 別の試行では、実行結果は一致しても、ルールで指定したヘルパーの値が直接埋め込まれた。データの抽出・整形でも必須のヘルパー・共通定数・API参照を保持し、前のカプセルの実装を壊さない指示を追加した。
- 注意書きだけの再試行では、エスケープされた引用符で後半の2件が途切れた。最終版では固定文字列の抽出補助を移行・修正用フォルダへ配置した。[PHPの文字列仕様](https://www.php.net/manual/en/language.types.string.php)に沿って引用符を解釈し、不完全な代入や扱えない式を黙って飛ばさない。PHP実行環境との照合テストも追加した。
- 抽出時に隣接カプセルの参照行を混ぜ、一時ファイルを許可外の場所に残して停止する試行もあった。抽出補助がカプセルの宣言した行範囲・連番・全行の存在を検査し、参照用の隣接行を拒否するよう変更した。一時ファイルは専用フォルダで許可し、移行先以外のアプリファイルや必須資料を変更する保護は維持した。
- データを置き換える際にクラス末尾の閉じ括弧が落ちた試行もあった。データ部分の前後を保存する指示を加え、処理済みの全カプセルを原文から照合するmain側の改善も統合した。
- 同じコンパイラエラーが大量に出ると、全文ログのサイズ制限で自動修正が始まらなかった。全行を読み、同じ診断だけをまとめるよう変更した。全文ログは保存し、末尾に対象外・解釈不能のエラーがある場合や、異なる診断が多すぎる場合は自動修正しない。
- 大きい原文では詳細の索引と全ソースの一覧を起動時に渡し、全カプセルを検索して必要な範囲を参照する。索引や原文を切り捨てる変更はしていない。
- 統合後の試行では、事前確認の結果から資料IDの拡張子が落ちて停止した。ハーネスが正しいIDのひな形を作り、Junieは適用可否と理由だけを記入するよう変更した。未判定・未知のID・不正な型は引き続き拒否する。

## 計測の読み方

入力合計にはキャッシュ読み込みを含み、キャッシュ作成は全試行0。トークンは保存済み`run.json`、Junie処理時間は`events.jsonl`のタスク開始から最終イベントまでを集計した。後者に起動・信頼確認待ち・ハーネス側のビルドやチェッカーは含まない。実経過時間は操作待ちの影響を受けるため、別に記録する。

改善前は比較のため、`2505f46`の事前確認関数だけを`ce025b9`の旧方式へ戻した。他の処理は`2505f46`のまま。中間1は抽出・ビルド診断を修正、中間2は大きい原文の索引供給も修正した`92cbf9b`。中間3・4はヘルパー保持の指示を加えた`9df82c1`。中間5は固定文字列の抽出補助を加えた`1d89df6`、中間6は指定行の検査と一時作業領域を加えた`3d711c7`。中間7はmainの全原文照合・索引一覧を統合した`3631aa7`。最終版は事前確認の結果ひな形も加えた`03e784c`。

改善前はビルド失敗で終了しているため、完走した最終版との全工程の時間・トークン差を高速化率には換算しない。事前確認にも実行ごとのばらつきがあり、短いPHPで測った約83%の時間短縮・約91%の入力削減は、2万行では再現していない。

## 再確認用のスクリプト

- `create_large_fixture.py 保存済み大量ルールケースのharness.local.toml`：同じ14原文をコピーし、2万行PHPと初回検査フックを作る。
- `analyze_large_runs.py ケースのルート before after-1 after-2 after-3 after-4 after-5 after-6 after-7 after-8 --expect-initial-failure before --expect-initial-failure after-2 --expect-initial-failure after-4 --expect-initial-failure after-5 --expect-initial-failure after-6 --expect-initial-failure after-7`：保存済みのRun・使用量・Junieイベントを照合する。失敗試行を明示しない限り、初回失敗を成功扱いにしない。

元のRunとworktreeを変更せずに確認できる。ルール選択の意味上の正しさはこの固定ケースでの結果であり、任意のPHP・ルール群への保証ではない。
