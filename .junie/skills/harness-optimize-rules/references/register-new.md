# 新しい原文を登録する場合だけ読む

既存TOMLのルールを見直す場合は、この手順を使わず [読み込み方の見直し](loading-policy.md) の `start` → `apply` を使う。以下は、まだ登録していない原文を整理して設定へ追加する場合の手順。

**書き込む前に、意味レビューで見つけた矛盾・未解決事項を確認する。** 同じ対象の相反する数値指定や義務・禁止などが未解決なら、整理済みファイルと設定案だけを残し、既存TOMLを変更せず利用者に判断を求める。たとえば同じタイムアウトに30秒と60秒の指定があれば、単に別ファイルへ配置しても解決していない。

既存登録を上書きせず、同じ原文が登録済みでないことをパスとバイト単位のSHA-256で確認します。既に登録済みなら通常の読み直し手順を使います。新規登録では次の順で作業します。

1. [読み込み方の見直し](loading-policy.md) と同じ `start` → ページ確認 → `check` で既存TOMLとルールを固定します。登録済みルールがなければページ確認は不要です。
2. `config.before.toml` から `config.proposed.toml` を作り、`tomlkit` または対象箇所だけのパッチで新しい登録だけを追加します。生成する場合は元の原文を `sources/` に置き、`rule_pack.py snapshot`、`build`、`verify` を先に通します。
3. `rule_review.py meaning PACK CANDIDATE --register-new` で今回の候補の意味レビューを作り、既存設定の場合と同じ根拠・未解決事項を記録します。生成物の場合はPACK内の固定原文、直接登録の場合は固定した登録する原文を参照します。
4. `rule_review.py apply PACK CANDIDATE --register-new` で照合します。不合格の候補は使用中TOMLに書き込まず、利用者の判断を待ちます。設定確認だけのために準備・移行・フックを起動しません。
