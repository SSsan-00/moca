# Runの保存形式と復旧

MoCAが読み込むのは、**現在の保存処理が作る形式**です。作成日時では判定しません。版番号を書かない記録も正常です。旧形式の自動変換、閲覧時の修復、起動時に全Runを探して書き換える処理はありません。

## どの状態なら続けられるか

| 場面 | 次にできること |
| --- | --- |
| 現行形式で、Run・対象・停止時点の版が一致する | 同じRunの保存・閲覧・再開。保存途中ならジャーナルと実ファイルを照合し、同じ操作を二重に適用しません。 |
| Runと成果物は使えるが、過去のビルド・検証条件・承認の版が証明できない | その合格・承認や「チェッカーから」は再利用せず、移行が完了した成果物を **ビルドから** 再検証します。移行完了前は通常の再開を選びます。 |
| 固定原文、対象一覧、未確定な編集、修正の試行履歴など、何を続けるかを特定できない | その記録からの操作を止めます。現在の設定・PHP・作業ツリーにある資料を、当時のものとみなして続けません。下の「手で引き継ぐ」を参照してください。 |

## 保存物と、その項目が必要になる時点

| 保存物 | 現行の形・正当な未作成状態 | 読み替えないもの／主な回帰テスト |
| --- | --- | --- |
| カプセルの原文（#336） | `capsule/manifest.json` に移行単位、順番付き `parts`、原文範囲、各パートの `sha256` と `segment_sha256`、固定原文の `php_sources` を保存。文字数・区間、固定資料・参照の一覧、構文境界の情報も記録します。固定PHPは相対パス・文字コード・保存先・ハッシュで照合します。準備未完了と、準備済みなのに資料が欠けている状態は区別します。 | 固定原文やパートの証明がない記録で元PHPを開き直すことはしません。[カプセル保存](../tests/runs/test_saved_queue_capsule.py)・[固定PHP](../tests/migration/test_capsule_prep_php_pinning_newlines_issues_2_3_7.py) |
| 共通ルール・資料（#337） | `rule_files` はルールなしなら空の配列。ルールがあれば `rules.json`・固定した本文・現在のガイド形式を照合します。共通参考資料はルールと別です。現行の番号付き資料を短縮できない場合は本文を欠落させません。 | 旧 `rule_chunks` を連結したり、旧 `legacy.md` を指示に使ったりしません。[ルール資料](../tests/rules/test_rule_materials.py) |
| Runと移行先（#338） | `run.json` のRun ID・プロジェクト・移行単位と `targets` が一致すること。移行先が1個でも一覧です。先頭の代表 `target` は設定・画面で使います。採用済み成果物の照合には対象ごとの `target_hashes` を使います。採用前にはまだハッシュがなくて構いません。 | 一覧や検証に必要なハッシュを単一の値から補いません。[Run保存](../tests/runs/test_saved_run_schema.py)・[複数対象](../tests/migration/test_multiple_targets.py) |
| エディタ（#339） | `editor.json` は保留編集と追加指示を持ち、初回未作成は空。保存要求は `save_id` と対象・基準版・保存内容で識別します。保存途中の `editor-save.pending.json` は、保存前後の版と確定予定の履歴、または保留編集の採用記録に結び付きます。 | 旧受付だけで成功や再送とみなさず、途中ファイルだけを空の履歴にしません。[保存中の復旧](../tests/editor/test_editor_save_recovery.py) |
| ダッシュボード待機列（#340） | `dashboard-queue.json` は `project_root`・`jobs`・`cancelled_conversations`・`blocked_conversations`。各ジョブに一意の `operation_id` が必要です。初回未作成と、保存された空の待機列は正常。再起動で自動起動するのは待機中の操作だけです。 | 保存後にIDを新しく作り直しません。不正な記録は起動せず保全します。[待機列保存](../tests/runs/test_saved_queue_capsule.py)・[Windows再起動](../tests/runs/test_windows_recovery_faults.py) |
| 検証・承認（#341） | 台帳や承認、チェッカー単独再開には対象ごとの版、実行条件と検証入力（対象ファイルなしでも `input_files: {}`）、必要なビルド証跡を照合します。承認は今回の指摘ID・理由・その指摘の対象ファイルの版に結び付きます。別の対象を編集しただけでは、この承認は消えません。Run全体を検証済みと扱うには全対象の版が一致する必要があります。準備・移行中にまだ証跡がないことは異常ではありません。 | 終了コード0や古い指摘ID、先頭の対象のハッシュだけでは承認や検証済みにしません。[台帳](../tests/runs/test_migration_ledger.py)・[チェッカー再開](../tests/verification/test_checker_resume_review_dashboard.py)・[ビルド証跡](../tests/verification/test_build_receipt.py) |
| Run設定・修正履歴・参照フォルダ（#342） | 準備時に選んだモデル・推論設定を使います。`null` は「既定値を使う」という保存済みの選択。参照資料は初回の採取と採取済みの復元を区別し、保存した対象・収集条件・各ファイルの版から復元します。既に準備した追従案を採用するときは採用時の参照版・下書き版を使い、同時に編集を取り込んだ場合はその編集履歴も照合します。 | 書かれていないモデル設定を現在値に置き換えたり、採取済みの資料を現在のworktreeから無断で作り直したりしません。確定できない修正試行は削りません。[Runモデル](../tests/runs/test_run_model_selection.py)・[参照資料](../tests/migration/test_source_context.py)・[追従・部分反映](../tests/migration/test_reference_refresh.py) |
| 停止下書き・チェックポイント | `draft.json` と番号付きファイルは `snapshot`、`base`、`targets`、`workspace_unchanged` と実ファイルを照合。番号は **manifestの順** で決まります。版を選択した場合は選択元と作業ツリーのスナップショットIDも必要です。 | 修正中の作業コピーを示す `base` / `targets` だけの記録は**現在も生成**されます。実ファイルと一致する場合の通常再開用であり、番号付き下書きの代わりにはしません。[下書きと版の照合](../tests/runs/test_target_snapshot_compatibility.py) |

作業メモは整数の `version: 1`、比較スナップショットはDiff Viewer形式の整数版1と保存元Runを照合します。これらの明示版と、版番号のないRun・カプセル等は別の契約です。未知の明示版や重複キーを、版番号なしや空の記録として扱いません。旧版スナップショットと差分を比べる機能、レガシーPHP・文字コードの入力対応、Windowsの共有違反後の再試行は、旧MoCA形式の自動変換ではありません。

## 手で引き継ぐ

1. 再開を繰り返さず、画面に出たRun ID、ファイル名、理由、利用したコミットを控えます。設定、Runディレクトリ、ログ、作業ツリー、未送信の編集を組として保全します。`.tmp` の削除やJSONのキー・ハッシュの手直しはしません。
2. どの変更を採るか元の環境で差分を確認します。旧版が必要なら保存先を分け、更新前の写しを使います。新旧のダッシュボードを同じ保存先に接続しません。手順は[Windowsの更新とロールバック](windows-release.md)を参照してください。
3. 現行設定で**新しいRun**を準備し、必要なソース・ルール・参考資料を指定します。必要な手修正だけをエディタへ引き継ぎ、移行・ビルド・チェッカーで改めて確認します。旧Run ID、受付・操作ID、承認、検証証跡を新しいRunへコピーしません。

[Windowsの必須CI](../.github/workflows/tests.yml)はPython 3.11/3.13それぞれで3シャードを実行します。形式モデル・トレース、実プロセスの異常終了・復旧、割り当てられた変異対照と実Chromiumは、それぞれ専用の[必須テストID](../tests/run_shard.py)で成功を確認します。全4変異を個別に試す手順は[復旧の検査](recovery-testing.md)にあります。これらの検査に本番PHP・移行後の業務処理・業務DBは使用しません。
