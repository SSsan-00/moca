# Runの保存形式と復旧

MoCAは既存の保存形式を使い続ける。閲覧時に旧記録を新版へ書き直さない。保存した処理が確定している場合は再開できるが、確認できない版や状態を成功とみなさない。判断は次の3つに分ける。

- **再開可能**：既存の形式・Run・設定・対象が一致し、再開条件を満たす。既存の停止柵や編集の照合は省略しない。
- **再検証が必要**：対象や検証証跡の版が合わない場合など。台帳上の完了やチェッカー単独再開に流用せず、既存の「ビルドから」など必要な工程を明示的に再実行する。
- **再開不可**：記録が壊れている、未知の版、違うRunや移行単位が混在した、途中保存だけが残った場合など。元のファイルを保持し、移行や下書き復元を開始しない。

| 保存物 | 確認する内容 | 受け入れる旧形式 |
| --- | --- | --- |
| `run.json` | Run ID・プロジェクト・移行単位・ターゲット・段階の型。再開時はカプセル数・進捗と元のコンテキスト設定も照合する。ビルド結果は真偽値を終了コードとみなさない。 | 単一 `target` と版番号なしの形式（例: `3ceaf59`）。後から追加されたモデル・検証・編集のフィールドはなくてもよい。現在の検証証跡がなければ再検証する。 |
| `editor.json` / `editor-save.pending.json` | 保留編集と指示、保存受付の対応、復旧前後の版と確定予定の履歴。記録がない通常の新規Runは空のエディタ。破損や途中ファイルだけの場合は空にしない。 | `d716964` の `immediate_saves` / `immediate_save_requests`。現行の受付番号・指示状態・採用記録がある場合も同じ版を基準に復旧する。 |
| `dashboard-queue.json` | プロジェクト、Run・移行単位・操作IDの重複、再開対象との一致、開始済みの停止柵。通常の待機一覧の読込では書き直さない。 | `c0d583c` の版番号なし・既存の待ち順・操作IDを持たない形式。廃止済みの操作は自動で実行しない。 |
| `capsule/manifest.json` | カプセル番号・保存ファイル・文字数・原文行や文字範囲。固定PHPの識別とハッシュ。移行単位が保存されていれば再開・台帳でも照合する。 | `798136e` の `parts`（番号・パス・文字数・原文範囲）。固定PHPが導入される前の記録には `php_sources` を要求しない。 |
| 作業メモ `context-handoff.json` | 整数の `version: 1`、原文・成果物の版、訂正元の内容とID。未知の版には追記せず、人が同じ内容を再登録した場合は壊れた履歴を残したまま新しい記録を採用する。 | 同じ整数版 `1`。メモを保存していないRunは、既存の原文と成果物で再開する。 |
| 停止下書き・チェックポイント | 停止記録と `draft.json` の版、対象ごとの内容。復元する版を選択済みの場合は、元の停止下書きと作業ツリーのスナップショットIDの両方が必要。番号付きファイルは保存時のmanifestの順で読み、後から変更されたRun JSONのキー順に依存しない。 | `ddb72be` / `375687a` の番号付き下書き。必要な版を確認できる旧 `base` / `targets` だけの作業領域下書きは通常再開を保つが、保存ファイルの復元計画には使わない。 |
| 比較スナップショット | Diff Viewer形式、整数 version 1、保存元Run、左右の本文。 | 同じversion 1。ほかの版や不完全な文書はViewerに渡さない。 |
| `harness.toml` | TOML構文と既存の構成スキーマ。読込に失敗してもファイルやRunを変更しない。 | 版番号なし・単一 `source` / `target` の書式。明示 `schema_version` は現行では定義していない。 |
| チェッカー単独再開用ビルド証跡 | 照合可能なビルド入力7項目と `bin` / `obj` のSHA-256。欠損や型不一致ならその証跡を根拠にせず、形が正しい証跡だけ既存の版照合に進む。 | 現行と同じ `a4e27af` 由来の版番号なし形式。証跡のない旧Runは通常の再ビルドが可能。 |
| 検証スクリプトの保存ログ | 指定ログ範囲の全体をハッシュで照合する。証跡を照合できない場合は再利用せず、ログを保持する。 | 全範囲のハッシュであることが記録されていない場合は、過去のログを確認し、必要な編集を新しいRunに引き継ぐ。 |

この一覧にない古い形式や不明な形式の復元は保証しない。壊れたJSON、同じキーの重複、未対応の明示版を既定値へ置き換えない。既存の閲覧・再開入口を使い、全Runや業務ファイルの追加走査は行わない。

## 破損に気づいたとき

1. 実行を止め、表示されたRun ID・ファイル名とログを控える。保存履歴や下書き、`.tmp` を削除・改名して再開しない。
2. 証跡が無効なだけなら、作業内容を確認して通常のビルド／チェッカーを実施する。以前の合格やチェッカー単独実行を再利用しない。
3. 版違いやRun記録の破損なら、元の版や信頼できる保存記録で確認する。それがない場合は元の記録を保持し、差分を確認して必要な手修正だけ新しいRunに引き継ぐ。Runの作業領域を確かめずに復旧処理を繰り返さない。

## 再現手順

Windowsの既存作業環境で、合成データだけを使う。実業務のPHP、生成アプリ、DB、Junieは起動しない。

```powershell
python -m unittest discover -s tests -t . -p "test_saved_*.py" -v
python -m unittest discover -s tests -t . -p "test_target_snapshot_compatibility.py" -v
python -m unittest discover -s tests -t . -p "test_build_receipt.py" -v
python -m unittest discover -s tests -t . -p "test_windows_recovery_faults.py" -v
```

旧形式の形は上記の実履歴から合成したもので、すべての過去のRunや保存失敗から復元できるという保証ではない。通常のRunの記録には今回新たな書式や追加の依存を導入していない。
