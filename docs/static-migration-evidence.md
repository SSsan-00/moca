# 移行台帳の静的証跡

実行タブで Run の **移行台帳** を開き、**静的証跡を確認** を押す。通常の台帳表示や移行・ビルド・チェッカーにはこの解析を挟まない。固定済みのPHPと現在の移行先を読み、PHP、生成アプリ、DBは実行しない。既存 .NET 9 SDK 付属のRoslynを利用する。台帳の工程完了は変更しない。

| 表示 | 何が分かったか |
| --- | --- |
| 明示条件を確認 | 設定で明示した宣言・リテラルについて指定範囲で独立した構文上の根拠を確認した。PHPとC#／Razorの意味が同じことは未確認。 |
| 明示条件の不一致 | 解析できた全指定範囲に、明示した構文上の事実がない。例: 必須の固定コードがコメントにしかない。対応先を一切指定していないだけの場合は不一致としない。 |
| 対応候補 | 保存アンカー、人が設定した範囲、AIの提案を出所別に表示する。全て範囲・版を照合するが、AI提案や同名だけでは確認済みにならない。 |
| 未確認 | 固定原文または対応先の証跡不足、未完了の区間、版のずれ、動的呼び出しや未解析構文など。漏れを断定しない。 |
| 対象外 | 参考として登録した原文、または固定版に対して設定で理由付き除外を宣言した範囲。移行済みとは数えない。 |

すべての割当範囲を元のIDで表示する。未索引の原文や旧Runでも範囲を黙って除外しない。固定前の過去Run、上限、SDK不足、文字分割が残る宣言などは該当部分が未確認。PHPの関数名・クラス・定数の字句情報は案内であり、実行されることや呼出し関係を示さない。Razorは原文に戻せる明示的なC#構文だけ確認でき、プロジェクト情報なしで存在しないことは断定できない。プリプロセッサの実設定や構文エラーで意味を推定しない。

## 明示条件・改名／分割／統合・対象外の指定

任意で、対象移行単位の既存TOMLに、アプリリポジトリ内のJSONを指定する。ファイルを作らない場合でも、既存アンカーと確認できていない範囲を表示する。

```toml
[[units]]
id = "orders"
source = "legacy/orders.php"
targets = ["Order.cs", "Order.cshtml", "Order.cshtml.cs"]
static_evidence = "migration-evidence/orders.json"
```

```json
{
  "version": 1,
  "entries": [
    {
      "kind": "mapping",
      "source": {
        "id": "1:1",
        "path": "legacy/orders.php",
        "start_line": 1,
        "end_line": 35,
        "sha256": "<表示した固定原文の64桁SHA-256>"
      },
      "origin": "human",
      "reason": "PHPの注文確認を計算と描画に分けて人が照合した範囲",
      "targets": [
        {"path": "Order.cs", "start_line": 25, "end_line": 80, "sha256": "<現在のOrder.csの64桁SHA-256>"},
        {"path": "Order.cshtml", "start_line": 10, "end_line": 21, "sha256": "<現在のOrder.cshtmlの64桁SHA-256>"}
      ]
    },
    {
      "kind": "require",
      "source": {
        "id": "1:1",
        "path": "legacy/orders.php",
        "start_line": 1,
        "end_line": 35,
        "sha256": "<同じ固定原文の64桁SHA-256>"
      },
      "reason": "業務側で定めた固定注文区分コード",
      "targets": [{"path": "Order.cs"}],
      "fact": {"kind": "literal", "value": "ORDER_PENDING"}
    }
  ]
}
```

- 範囲ID・パス・開始行・終了行・原文SHA-256は、表示された同じ行の値を使う。対象SHA-256は現行ファイルの版（Windowsでは `Get-FileHash -Algorithm SHA256` の値を小文字にする）。文字単位に分割された範囲は、行だけの指定で確認済みや対象外にしない。
- `mapping` の出所は `human` または `ai`。名前は一致しなくても指定できる。1範囲に複数の移行先を挙げれば分割、複数原文から同じ移行先を指せば統合。人の指定も構造上の関連付けであり、独立検査の合格とは別。
- `require` は `method`、`type`、`property`、`const` の宣言名、または `literal` の固定文字列値（エスケープ展開後）を対象とする。どれか1つの指定範囲内で検出する条件。範囲指定には現在のハッシュが必要だが、パスのみで全体を対象にもできる。コメントやメソッドを呼んだだけでは宣言に該当しない。オーバーロードの意味、実行可能性、動的な文字列やルールの妥当性は検査しない。
- 意図的な削除は `kind: "exclude"`、`source`、空でない `reason` だけ。別の判定と同じIDに混ぜない。ファイルは検査時に読取るだけで、モデル入力・コード生成・自動修正には使わない。

## 検証

Windowsで既存環境を使い、下記の合成テストを実行する。既存のPHP語彙を含む改名、分割、統合、欠落の模擬規約、対象外、動的・混在構文、旧Runを検査する。

```powershell
python -m unittest discover -s tests -p test_static_migration_evidence.py -v
python -m unittest discover -s tests -p test_roslyn_static_evidence.py -v
```

合成期待値を独立して用意した主ケースは範囲10件。明示欠落の1件を検出し、正例や対応候補・対象外・判定不能を誤って不一致にしない。動的・未索引の2件を意図的に未確認とする。この固定ケースは実案件の偽陽性・偽陰性の率の推定ではない。
