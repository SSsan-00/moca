# WindowsでPHPからC#へ移行する手順

Windowsのダッシュボードから、PHPをC#やRazorへ移行する手順です。まずは小さいPHPファイル1つで **設定保存 → 準備 → 同じRunで移行** を試します。設定はフォームから入力でき、ルール・参考実装・チェッカー・自作スクリプト・差分ビューアーは必要に応じて追加します。

ハーネスを置くフォルダと、移行するアプリのGitリポジトリは分けます。アプリには `dotnet build` でビルドできるC#／Razorプロジェクトが必要です。PHP原文と参照資料はアプリ外にも置けます。PHPだけのリポジトリの場合は、先に移行先プロジェクトの雛形を用意してください。Junieには指定した移行先ファイルの編集を依頼します。実行順序と保存データの詳細は [技術仕様](../SPEC.md) を参照してください。

## 1. ダッシュボードを起動する

開発環境に.NET SDK 9以降が導入済みという前提で、既存SDKを使います。通常はSDKの追加インストールは不要です。

Windows TerminalなどでPowerShellを開き、次を確認します。コマンドが見つからなければ、表の公式サイトから導入し、PowerShellを開き直して再確認します。

| ツール | 確認コマンドと合格条件 | 未導入の場合 |
| --- | --- | --- |
| Python | `py -3 --version` が3.11以上を表示する。3.13などでも使えます。 | [Python for Windows](https://www.python.org/downloads/windows/) |
| Git | `git --version` がバージョンを表示する。 | [Git for Windows](https://git-scm.com/downloads/win) |
| Junie CLI | `junie --version` がバージョンを表示し、対話起動でログインできる。移行時に必要です。 | [Junie CLIのセットアップ](https://junie.jetbrains.com/docs/junie-cli.html) |
| .NET SDK | 導入済みの9以降を使用します。アプリの場所で `dotnet --version` が成功することを確認します。 | SDK選択に失敗した場合のみ、以下の指定を確認します。 |

`py`がなくても `python --version` が3.11以上なら、以下の `py -3` を `python` に置き換えられます。複数版がある場合は、確認した版を `py -3.13` のように指定できます。3.11を追加で入れる必要はありません。

JunieのWindows用インストールコマンドは次のとおりです。導入済みなら再実行は不要です。 [公式手順](https://junie.jetbrains.com/docs/junie-cli.html)

```powershell
powershell -NoProfile -Command "iex (irm 'https://junie.jetbrains.com/install.ps1')"
```

移行前に同じWindowsユーザーのPowerShellで `junie` を起動し、画面の案内に従ってログインします。バージョン表示だけではログインを確認できません。認証情報は本人の端末で入力します。

SDKの確認は、ハーネスのフォルダから次のように行います。パスは実際のアプリに置き換えます。

```powershell
Push-Location -LiteralPath 'C:\work\LegacyApp'
dotnet --version
Pop-Location
```

成功すれば、そのSDKを使って進めます。既存の `global.json` がある場合は、指定版と `rollForward` の条件を確認します。指定がなければ通常は導入済みの最新SDKが選ばれます。SDKを固定するために新しい `global.json` を作る必要はありません。 [SDKの選択方法](https://learn.microsoft.com/en-us/dotnet/core/tools/global-json)

選択に失敗した場合だけ、`dotnet --list-sdks` と有効な `global.json` を照合します。指定を満たすSDKが不足していれば [公式サイト](https://dotnet.microsoft.com/en-us/download) から追加します。既存のSDK指定やビルド対象のフレームワークは、セットアップの都合で変更しません。Runtimeだけが導入されている場合はSDKも必要です。

ダッシュボードの設定と **準備** はPythonとGitで試せます。準備用スクリプトを登録した場合は、その実行環境も必要です。

初回は作業フォルダで次を実行します。

```powershell
git clone https://github.com/SSsan-00/php-to-csharp-migration-harness.git
Set-Location .\php-to-csharp-migration-harness
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\php-to-csharp-harness.exe --help
.\h.cmd d
```

1行ずつ実行し、エラーが出たらその段階を解決してから進みます。既にclone済みならそのフォルダへ移動し、使える `.venv` があれば作り直す必要はありません。`--help` にコマンド一覧が出ればインストール完了です。仮想環境を直接呼ぶため、`Activate.ps1` の実行やPowerShellの実行ポリシー変更は不要です。

次回以降はハーネスのフォルダで `.\h.cmd d` を実行します。端末に表示された `http://127.0.0.1:.../` のURLを、末尾の文字列まで含めてブラウザーで開きます。起動したPowerShellは開いたままにします。Junieの入力や確認はそこで行います。初回は設定ファイルがなくても開けるため、設定例をコピーする必要はありません。

| つまずいた場合 | 確認すること |
| --- | --- |
| `py`・`python`が見つからない／3.11未満 | Pythonを導入し、PowerShellを開き直してバージョンを確認します。利用可能な3.11以上の版で仮想環境を作ります。 |
| `pip install`が失敗する | `pyproject.toml` があるハーネスのフォルダで実行しているか確認します。ダウンロードに失敗した場合は社内プロキシや証明書の設定を確認します。 |
| `h.cmd`に未インストールと表示される | `.\.venv\Scripts\python.exe --version` と、上の `pip install` の結果を確認します。既存の `.venv` は原因を調べてから修復します。 |
| ダッシュボードに接続できない | 起動元のPowerShellと、今回表示されたURL全体を確認します。再起動するとURLは変わります。 |

既にセットアップ済みの場合は、実行が一区切りついてからハーネスを終了し、同じフォルダで更新します。保存済みの設定とRunを使ってダッシュボードを起動できます。

```powershell
git pull --ff-only origin main
.\.venv\Scripts\python.exe -m pip install -e .
.\h.cmd d
```

## 2. 移行元と移行先を設定する

ダッシュボードの **設定** タブを開きます。初回は設定例が表示されるので、**プロジェクトの詳細設定** を開いて実際の場所を入力します。表のパスは例です。

| フォームの項目 | 入力例と役割 |
| --- | --- |
| アプリのリポジトリ | `C:/work/LegacyApp`。移行先とC#のビルド対象を置くGitリポジトリのルートです。 |
| 作業ツリーの保存先 | `C:/migration/worktrees`。Runごとに移行先の作業コピーを作ります。 |
| 実行データの保存先 | `C:/migration/runs`。Run IDごとのカプセル、台帳、実行ログが入ります。作業ツリーとは別のフォルダを使います。 |
| 機能名（ID） | `メニュー` や `menu` など、設定内で一意の名前です。 |
| 移行元PHP | `legacy/menu.php`。アプリルートからの相対パス、または外部ファイルの絶対パスです。拡張子なしを含め、拡張子を問わず移行元PHPとして全文を読み込みます。 |
| 移行先（1行に1ファイル） | `src/Web/Pages/Menu.cshtml.cs` と `src/Web/Pages/Menu.cshtml` を別々の行に入力します。Junieが編集するファイルをここで指定します。 |
| ビルド対象 | **プロジェクトの詳細設定 → ビルド・独自チェッカー** に `src/Web/Web.csproj` などを指定します。アプリルートからの相対パス、またはアプリ内の絶対パスで、`.csproj`、`.sln`、`.slnx` が使えます。空欄ならルートでビルドします。 |

**アプリのリポジトリ** と2つの保存先は、絶対パス、または設定ファイル（通常は `harness.local.toml`）の場所からの相対パスで指定できます。**アンカーの参照JSON（任意）** も同じ基準です。

移行元・ルール・参考実装・差分ビューアーのHTML・仮C#のコピー元は、アプリルートからの相対パス、またはアプリ外も含む絶対パスで指定できます。**移行先** と **ビルド対象** は、絶対パスでもアプリリポジトリ内に限ります。ハーネスがworktree内のパスへ変換して編集・ビルドするため、元のリポジトリには書き込みません。フォームではパスに引用符を付けません。

Razorページは、同じディレクトリと名前の `.cshtml` と `.cshtml.cs` を両方指定します。相方が不足している場合、設定の保存時に必要なパスが表示されます。通常のC#ファイルは1つから指定できます。

保存先の2つのフォルダは、アプリとハーネスの両リポジトリの外に置き、互いに入れ子にせず指定します。新しい機能は **移行単位を追加** から入力できます。既存の移行単位は **編集する移行単位** で選びます。

左側の **プロジェクトの詳細設定** を開くと、リポジトリ、保存先、ビルドとチェッカーの設定を編集できます。作業ツリーは既定でアプリの現在の `HEAD` から作ります。必要に応じて **作業ツリーの基準リビジョン** にブランチ名、タグ名、コミットIDを指定します。同じ欄でカプセルの文字数上限、Junieのステップ数上限、差分ビューアーも設定できます。カプセルの文字数上限は空欄なら500,000文字です。

PHP原文と参照資料は準備時点の指定ファイルから読み取るため、未コミットの内容も使えます。ビルド対象・依存ソース・チェッカー・準備後以降のスクリプトは基準コミットに含めておきます。これらの未コミットの変更はworktreeに入りません。移行先には新規ファイルも指定できます。Junieの作業フォルダには、移行先ファイルの親フォルダ、その隣の `inc`、`inc` より1階層上の `Libs` と `Extensions` を、worktreeに存在するものだけ同じ相対パスで取り込みます。たとえば `src/Web/Pages/Orders/Index.cshtml.cs` なら `src/Web/Pages/Orders/`、`src/Web/Pages/inc/`、`src/Web/Libs/`、`src/Web/Extensions/` です。移行先以外は参照専用です。

準備の前に、アプリの状態とコミットの有無を確認します。パスに空白がある場合も、このように引用符で囲みます。

```powershell
git -C 'C:\work\LegacyApp' status --short
git -C 'C:\work\LegacyApp' rev-parse --verify HEAD
```

2つ目のコマンドが失敗した場合は、アプリの初回コミットが必要です。必要なビルドファイルなどが `??`（未追跡）や変更ありと表示された場合も、採用する内容を確認してアプリ側でコミットします。関係のない変更までまとめてコミットする必要はありません。別の基準リビジョンを使う場合は、その版に必要なファイルが入っていることを確認します。

**設定を保存** の成功メッセージを確認します。入力した内容は `harness.local.toml` に保存されます。保存は設定形式の検証で、入力ファイルの読み込みやビルドの成功は後の工程で確かめます。

## 3. 移行ルール、参考実装、独自チェッカーを追加する

プロジェクト固有のルールはMarkdownファイルに保存します。アプリ側に置く場合は、たとえば共通メソッドの使い方を `docs/migration/common.md`、画面の表示条件やRazorの規約を `docs/migration/razor.md` に書きます。散在する既存ルールを整理する場合は、下記のハーネス側の専用フォルダも使えます。

**設定** の **プロジェクト共通の移行ルール** で **移行ルールを追加** を押して **ルールファイル** にアプリルートからの相対パス、または外部ファイルの絶対パスを入力します。複数ある場合はファイルごとに追加します。不要な項目は、そのルールの **×** で設定から外せます。入力を確認し、**設定を保存** を押します。

**設定** 左側の **プロジェクトの詳細設定** を開き、**ビルド・独自チェッカー** を入力します。

| 項目 | 入力方法 |
| --- | --- |
| チェッカーの実行ファイルと引数 | 1行目から順に `py`、`-3`、`-X`、`utf8`、`tools/check_migration.py` を入力します。チェッカーに必要なパッケージがあるPythonを使います。移行単位にも共通設定にも指定がなければ実行しません。 |
| 自動修正回数 | 1つのRunでビルドエラーとチェッカー指摘をJunieが修正する合計上限です。空欄は2回、`0` は自動修正なしです。 |

コマンドを一行にまとめず、実行ファイルと各引数を改行して入力します。パスに空白があっても、フォームでは引用符を付けません。チェッカーはビルド成功後、作業ツリーのルートで実行します。依存パッケージは、チェッカーを起動するPythonなどの実行環境に導入してください。ハーネスのインストールだけでは導入されません。

移行単位ごとにチェッカーを変える場合は、**移行単位** で対象を選び、**この移行単位のチェッカー（任意）** に実行ファイルと各引数を1行ずつ入力して保存します。空欄なら **プロジェクトの詳細設定** の共通チェッカーを使い、共通設定も空欄なら実行しません。CLIの `--checker-command` を指定した場合は、それを最優先します。再開時にも対象の移行単位の設定を使います。TOMLでは対象の `[[units]]` に `checker_command = ["py", "-3", "tools/check_orders.py"]` のように記述します。

`py` が使えず `python` やPythonの実行ファイルのパスを指定する場合は、`-3` の行を取り除き、`-X`、`utf8`、スクリプトのパスを続けます。`-3` などの版指定は `py` 専用です。

チェッカーは、合格なら終了コード `0`、指摘があれば正の終了コードを返すようにします。ダッシュボードで指摘箇所の表示や判断を使う場合は、UTF-8で次の形式に揃えます。既存チェッカーの形式が異なる場合は、案件側のラッパーで変換できます。

```text
MIG101 src/Web/Pages/Menu.cshtml.cs:12 warning: 共通メソッドを使ってください
```

**自動修正回数** が空欄なら、1つのRunにつき最大2回の自動修正を試み、その都度ビルドとチェッカーを実行します。`0` を指定すると指摘を保存して人の確認を待ちます。自動修正に渡す指摘は設定済みの移行先を指す必要があります。指摘と混ざるサマリーなどの出力は、必要に応じて別ログに分けます。

移行元PHPの文字コードは既定で自動判定します。既存の設定に `source_encoding` や移行単位の `[[units.inputs]]` がある場合も読み込めます。

### 移行済みのPHPとC#／Razorを参考にする

**設定** の **プロジェクト共通の参考実装** で **参考実装ペアを追加** を押し、**参考実装の元PHP** と **移行済みC#／Razor** にそれぞれアプリルートからの相対パス、または外部ファイルの絶対パスを入力します。元PHPに対応するRazorページ本体（`.cshtml`）とPageModel（`.cshtml.cs`）を登録する場合は、ペア内の **移行済みファイルを追加** で入力欄を増やし、1ファイルずつ指定します。セットごと設定から外す場合は、ペアの末尾にある **×** を押し、**設定を保存** します。設定から外してもファイル自体は削除されません。

元PHPと対応する移行済みファイルを例ごとに同じフォルダに置くと、Junieが対応を読み取りやすくなります。たとえば元PHPに `docs/migration/examples/orders/orders.php`、移行済みファイルに同じフォルダの `Orders.cshtml` と `Orders.cshtml.cs` を登録します。別の例は新しいペアとして追加します。

共通ルールと参考実装は、ファイルのパスを指定すると準備時に全行を読み込みます。ルールと参考実装はカプセル本文と別に保存します。

各ルールの「読み込み方」で「毎回適用する必須事項」か「必要時に読む詳細・例」を選びます。分類を指定していない既存ルールは必須事項として扱います。必須事項は全文をJunieの起動時の指示に渡すため、断片ごとの読み取り待ちはありません。詳細・例は「読む場面・内容」を入力し、該当する移行・修正で原文を読みます。分類の変更は次に準備するRunから適用され、保存済みRunは当時の内容を引き継ぎます。ダッシュボードが自動で分類することはありませんが、下記のスキルで設定の見直しを依頼できます。

移行の初回編集前に、Junieが保存済みの移行元と各詳細の「読む場面・内容」を照合します。短い索引と移行元は全文をまとめて渡します。原文が長い場合は索引とソース一覧を起動時に渡し、全カプセルを検索して関連範囲を読みます。索引も長い場合は両方をファイルで参照し、原文は切り捨てません。ハーネスが全件分の判定を検証してRunに保存し、修正・再開でも使います。該当と判断した詳細や移行先が明記された詳細の原文を起動時に渡し、そのほかの原文はRunの準備資料に保管します。説明には移行元の処理やデータの特徴も記載してください。

規約を守ったかは独自チェッカーでも確認します。Junieは移行・自動修正時に、参考実装の関連箇所を読みます。参考用のPHPは移行台帳の対象外です。既存の移行単位に登録した共通資料は、設定画面に引き継がれます。

### スキルで読み込み方を最適化する・原文を整理する

[ルール整理スキル](../.junie/skills/harness-optimize-rules/SKILL.md) は原文を要約せず、全行を保持して必須事項と詳細へ分けます。ハーネスのフォルダで `junie` を起動し、`/skills` で `harness-optimize-rules` が有効なことを確認して、Junieの入力欄へ次を送ります。

**登録済みのルールの読み込み方を見直す場合:**

```text
/harness-optimize-rules harness.local.toml の「プロジェクト共通の移行ルール」の読み込み方を最適化して、設定へ反映してください。
```

内容を確認して必須／詳細を見直し、詳細の「読む場面・内容」も具体化します。整理済みのファイルは本文を変えず設定だけ更新し、必須と詳細が混在するファイルは全行を保持して分割します。変更理由と必須本文の文字数の前後も報告します。

全ページを確認してから分類・設定反映します。確認記録は少量ずつ保存するため、未記録の読み飛ばしや引用の転記ミスをその場で検出できます。大量のルールを整理する場合は、`junie --max-steps 200` のように起動時のステップ数を増やせます。上限で止まった場合は、同じ対話で保存済みの確認記録から続きを依頼します。

**新たに原文を整理する場合:**

```text
/harness-optimize-rules C:/migration/loose-rules の全ルールを、情報を落とさず Agent.md と用途別の詳細へ整理してください。
保存先は rule-workspace/LegacyApp、既存設定は harness.local.toml です。TOMLは変更せず設定方法を案内してください。
```

設定の反映も任せる場合は、最後を「TOMLへの反映もお願いします」に置き換えます。スキルは専用フォルダに原文のコピーを残し、空行・例・例外も含めて全行の対応を検証します。条件や優先順位も確認し、未解決の矛盾があれば設定反映を保留します。

整理後は **プロジェクト共通の移行ルール** に次のように登録します。ファイル名だけでは必須扱いになりません。

| ファイル | 読み込み方 |
| --- | --- |
| `generated/Agent.md` | **毎回適用する必須事項** |
| `generated/details/*.md` | **必要時に読む詳細・例**。**読む場面・内容** も設定 |

スキルに設定反映を任せると、バックアップ後に対象の旧ルールだけを置き換え、他の設定を保持します。`generated/rules.toml` は設定の断片なので、既存TOML全体を上書きしないでください。設定確認のために準備・移行を実行することはありません。

新しく生成するAgentは、Junieの起動時に渡された必須・詳細の原文と、まだ本文を読んでいない資料を区別して案内します。提供済み本文の重複取得を避け、編集後に適用条件・例外と結果を照合します。既存PACKの原文・生成物は上書きしません。

対応形式・手動手順は [rule-workspaceの案内](../rule-workspace/README.md) を参照してください。登録後は生成物を移動・削除せず、修正時は別の作業領域で作り直します。新設定は次に準備するRunから適用されます。原文と生成物はGit管理の対象外なので、必要に応じて別途バックアップします。

## 4. 独自スクリプトを使う

**設定** の **自作スクリプト** で **スクリプトを追加** を押し、実行工程を選びます。コマンドの1行目に実行ファイル、2行目以降に引数を1つずつ入力します。たとえばPowerShellで前処理を実行する場合は、工程に **準備前** を選び、次のように入力します。

```text
powershell.exe
-NoProfile
-File
tools/prepare-legacy.ps1
```

設定は全移行単位に適用されます。同じ工程を選んだスクリプトは、フォームの上から順に実行します。相対パスの基準は工程ごとに異なります。

| 工程 | 実行場所とタイミング |
| --- | --- |
| 準備前 | アプリのリポジトリで実行します。PHPや参照資料を生成する場合はここを選びます。 |
| 準備後、Junie移行前、Junie移行後 | Runの作業ツリーで各工程につき1回実行します。準備後にはカプセルが作成済みです。移行先を変換してからビルドしたい場合はJunie移行後を選びます。 |
| ビルド前、ビルド成功後 | Runの作業ツリーで、再検証や自動修正に伴うビルドでも実行します。 |
| チェッカー実行前、チェッカー実行後 | チェッカーを設定した場合にRunの作業ツリーで実行します。実行後のスクリプトはチェッカーが指摘を返した場合も実行します。 |

スクリプトが失敗すると（終了コードが0以外）、その工程で停止します。**進捗** の実行ログから工程とログファイルを確認してください。準備前のスクリプトで停止したときは修正後に準備か移行を開始し直します。準備後以降は同じRunを再開できます。準備後とJunie移行の前後で失敗したときは、設定順と引数が一致する成功済みコマンドを飛ばし、残りから再開します。ビルド・チェッカーの前後で失敗したときは、ビルド工程から再検証します。

作業ツリーから相対パスで呼び出すスクリプトは基準コミットに含めます。指摘を画面に表示し、Junieによる自動修正の対象にする検証は、**チェッカーの実行ファイルと引数** に設定します。

PowerShellのラッパーをチェッカーにする場合は、同じ欄に以下を入力します。`tools/check-migration.ps1` と呼び出すスクリプトは、作業ツリーの基準コミットに含めます。

```text
powershell.exe
-NoProfile
-File
tools/check-migration.ps1
```

### 別ディレクトリの仮C#を取り込む

たとえば、**移行元PHP** に `legacy/menu.php`、**移行先** に `src/Web/Services/MenuService.cs` を指定します。**移行先** はJunieが編集し、最終結果を置くファイルです。仮C#がある場合は、そのファイルの初期内容として取り込めます。

設定画面の **移行単位** の下にある **仮C#の取り込みを追加** を押します。**仮C#のコピー元（絶対・相対パス）** に `C:/migration/draft/generated/module/Services/MenuService.cs` などの絶対パス、または `draft/MenuService.cs` などのアプリルートからの相対パスを入力し、**設定を保存** します。選択中の移行単位に移行先が1ファイルだけあれば、そのパスが自動で選ばれます。複数ある場合は **移行先ファイル** の一覧から選んでください。

取り込みは **Junie移行前** に実行されます。ハーネスが付属の `tools/copy_migration_draft.py` を自動で読み込みます。コピー元の相対パスはアプリルートを基準に解決します。コピー先の絶対パスもアプリ内に限り、worktree内のパスへ変換します。元のリポジトリには書き込みません。コピー先のフォルダは自動で作成し、ファイルがあればRunのworktree内で上書きします。コピー元が見つからない場合はその工程で停止します。Junieが編集したファイルは同じ配置先に反映され、ビルドに進みます。

取り込みは設定内の全移行単位に適用します。移行単位ごとに異なる取り込み設定を使う場合はTOMLを分けます。以前のダッシュボードで保存した取り込みも表示されます。以前の配置先を移行先から外している場合は、登録済みの移行先を選び直してください。進捗デモでは注文履歴の取り込み例を編集できます。

## 5. ダッシュボードから実行する

1. **設定を保存** を押し、保存できたことを確認します。
2. **実行** タブで移行単位を選び、初回は **準備** を押します。準備前・準備後のスクリプトを設定していれば、ここで実行されます。成功したら **進捗** にRun IDとカプセルが表示され、実行データの保存先に `<Run ID>/run.json` と `capsule/manifest.json`、作業ツリーの保存先に `<Run ID>/` ができます。この時点ではJunie・ビルド・チェッカーは未実行です。
3. Junieのログインと.NET SDKを確認してから、**保存済みの実行** でそのRun IDを選び、**移行を再開** を押します。**進捗** の **同じ実行を再開** でも続けられます。**移行を実行** は準備から新しいRunを作る操作です。Junieの作業フォルダー確認が出たら、ダッシュボードのダイアログでパスを確認し、**信頼して続行** を選びます。移行時はRunの `agent-workspace` が表示されます。対象のソースと参照資料がJunieのサービスに送られ、カプセルごとに移行します。
4. **進捗** で工程ごとの経過時間と実行状況を確認します。Junieのイベントがない間も約3秒ごとに稼働状況を表示します。操作の許可待ちになったら、ダッシュボードの確認ダイアログで応答します。**停止** で編集を残して止め、同じRun IDで **移行を再開** できます。停止中は時間を加算せず、中断だけで修正回数を消費しません。worktree作成前に止めた場合は準備からやり直します。
5. **比較ツールを開く** で、準備時のPHPと最新の移行先を確認します。Junie実行中は保存済みの編集中ファイルも表示できます。開いた後の編集を見るには再度比較を開いてください。移行元や移行ルールを変えた場合は、新しいRunを開始します。再開では準備時のカプセルを使い、処理済みのカプセルを飛ばします。

| 止まった場所 | 確認と再開の手順 |
| --- | --- |
| 準備 | カプセル作成に失敗した場合は、移行元や資料のパス、文字コード、カプセルの文字数上限を確認します。作業ツリーの作成前に止まるため、設定を修正して新しく実行します。 |
| Junieの起動 | 画面の `Executable`（解決した実行ファイル）、`Command`、`CWD`（起動場所）と例外の詳細を確認します。`.BAT`・`.CMD` も対応しています。インストールやPATH変更後はPowerShellを開き直し、同じRunを再開します。起動できなかった試行は修正回数に含めません。 |
| Junieの移行 | 進捗画面の **Junie の確認を開く** や、エディタの質問欄を確認します。中断後に **移行を再開** を押すと、未完了のカプセルから続けます。途中で移行先を外部編集した場合は、再開前に差分を確認します。 |
| モデルサービスとの通信 | Junieが通信失敗を確定すると、ハーネスが同じ作業場所で最大2回起動し直します。復旧しなかった場合は、接続を確認して同じRunを再開します。 |
| ビルド・チェッカー | Runの `build.log` または `checker.log` を読み、必要な修正後に同じRunを再開します。移行済みのカプセルは処理済みとして扱い、ビルドから再検証します。 |
| Junieの自動修正 | 同じRunを再開するとビルドから再検証し、指摘が残っていれば修正を続けます。中断した試行は修正回数に含めません。指摘と移行先が一致する場合は保存した下書きも引き継ぎます。 |

ビルドできない場合は、Runのworktreeに指定したプロジェクトやスクリプトがあるか、SDKが `global.json` の条件に合うかを確認します。アプリ側で後からコミットしても、準備済みのworktreeは更新されません。基準コミットを変えた場合は新しいRunで準備します。

エラー詳細には例外の原因と呼び出し履歴、取得できた標準出力・標準エラーを省略せず表示します。長い場合は表示欄をスクロールできます。Junieの起動失敗時は、特定できたJunieログのエラーも表示します。認証情報とプロンプト本文は伏せ字にします。

移行先を手修正する場合は **エディタ** で対象ファイルを開き、**保存** を押します。Junieの実行中に登録した編集と追加指示は、現在の区間が終わってから取り込みます。同じ箇所で競合した場合は、修正内容を調整して **競合を解消して保存** を選びます。Junieから手修正の意図について質問が表示されたら、回答を追加指示で送り、進捗画面から同じRunを再開します。

## 6. 差分を確認して移行を完了する

ダッシュボードの **移行台帳** でPHPの範囲と範囲IDを確認します。**差分を開く** を使う場合は、付属のDiff Viewerをアプリ側へコピーし、**プロジェクトの詳細設定** の **差分ビューアーのHTML** に `tools/dist/index.min.html` を指定します。HTMLにはアプリルートからの相対パス、またはアプリ外の絶対パスも指定できます。次はハーネスのフォルダからコピーする例です。

```powershell
$viewerDir = 'C:\work\LegacyApp\tools\dist'
New-Item -ItemType Directory -Path $viewerDir -Force | Out-Null
Copy-Item -LiteralPath .\tools\dist\index.min.html -Destination $viewerDir
```

**差分ビューアー** で **使用しない** を選ぶか、HTMLを空欄にすると比較とアンカー生成が無効になります。設定したHTMLのパスを残したまま切り替えられます。準備、移行、ビルド、チェッカーは実行できます。作業ツリーで `git status --short` と `git diff` を使って差分を確認できます。

ビューアーを有効にして **Junieで対応行を提案して開く** を選ぶと、今回の比較から対応行を提案します。**プロジェクトの詳細設定 → アンカーの参照JSON（任意）** に手本となるDiff ViewerのワークスペースJSONのパスを1行に1つ入力します。指定した各ファイルの手動アンカーを先頭から最大12件使います。絶対パス、または設定ファイルの場所からの相対パスで指定します。空欄なら同じRunの確認済み対応例を自動参照します。指定ファイルがない・JSONが不正な場合はエラーになり、自動参照には切り替えません。パスとJSONを直すか、空欄に戻して保存してください。この操作には移行とは別のJunie呼び出しが発生します。 `--task` に対応したJunieでは、アンカー生成を非対話モードで実行します。非対応なら従来の起動方法を使います。

移行台帳は閲覧用です。判断はハーネスのフォルダからCLIで記録します。次の例の `RUN_ID` と `1:1` は画面の値に置き換えます。同じ理由と移行先で複数範囲を確認した場合は、`--range` を繰り返します。

```powershell
.\.venv\Scripts\php-to-csharp-harness.exe ledger-review --config harness.local.toml --run-id RUN_ID --range 1:1 --state confirmed --target src/Web/Pages/Menu.cshtml.cs --target src/Web/Pages/Menu.cshtml --reason "元PHPと画面およびPageModelの対応を確認"
```

対象外の範囲を記録する場合は `--state excluded` と `--reason` を指定します。現時点の入力でビルド、設定済みの検証スクリプト、チェッカーの条件を満たし、全範囲が確認済みか理由付きの対象外になると、画面に **移行完了** が表示されます。確認後に移行先を変更すると、対応する範囲が **要再確認** に戻ります。

チェッカーの指摘を修正不要と判断した場合は、進捗画面の確認ダイアログで指摘を選び、理由を入力して **問題なしとして記録** します。**同じ実行を再開** し、承認済みの指摘だけが残る場合もチェッカーの条件を満たします。

Junieが作業フォルダーの信頼確認や操作の許可を求めると、同じダイアログに確認内容と選択肢が表示されます。閉じた場合は進捗画面の **Junie の確認を開く** から再表示できます。

## Junieに設定手順を案内させる

ハーネスのリポジトリに [操作案内スキル](../.junie/skills/harness-setup/SKILL.md) が入っています。Junieを導入・ログインした後、**ハーネスのフォルダ** で `junie` を起動します。`/skills` で `harness-setup` が有効なことを確認し、Junieの入力欄へ次のように送ります。PowerShellのコマンドとして入力するものではありません。 [JunieのAgent Skills](https://junie.jetbrains.com/docs/agent-skills.html)

```text
/harness-setup 初めて使います。小さいPHPの準備まで手伝ってください。
WindowsのPowerShellを使っています。
アプリ: C:/work/LegacyApp
移行元: legacy/menu.php
移行先: src/Web/Pages/Menu.cshtml.cs と src/Web/Pages/Menu.cshtml
ビルド対象: src/Web/Web.csproj
ルール・参考実装・チェッカー・スクリプトはまだありません。
```

既存の設定やエラーがある場合は、その場所とエラー内容を伝えます。スキルが必要な環境確認、設定項目、次の操作を案内します。変更を任せずに確認したい場合は「ファイルは変更せず、案内だけ」と添えます。

一覧に出ない場合は、ハーネスのチェックアウトに `.junie/skills/harness-setup/SKILL.md` があるか確認し、そのフォルダでJunieを起動し直します。`/skills` で無効になっている場合は有効にします。Junie自体がまだ使えない場合は、先にこのマニュアル第1節で導入します。

ハーネスが実際の移行で起動するJunieは、Runごとの `agent-workspace` をプロジェクトとして開きます。案件の移行ルールは、設定フォームの **プロジェクト共通の移行ルール** に登録します。
