## 現在の合格条件と残り

- 本番のdotUltimate付属JetBrains AIでのJunie接続は利用者が確認済み。このWindows試験環境に有料のJetBrainsライセンスは追加せず、実Junieの検証では登録済みのOpenAI BYOKを使う。
- トークン数・時間は比較用の参考値。トークン数が減ることは採用条件にしない。必要なルール、条件・例外・優先順位、根拠行と移行結果の正しさを優先する。
- 固定参照のON/OFFは実Junieで合成資料の読み取りに成功したが、ACPホストに対する読取・確認要求は両方0件。自動化による確認削減と、実Junieがルール整理中に出す操作確認への回答は実機では未確定。
- 静的デモの通知は模擬操作だけで、Windowsへの発行やJunieの実行は行わない。デスクトップ用の検証ツールは別。Windowsの通知OFF・集中モード等との組み合わせは目視で確認する。

- 実Junieの同一合成比較を、対象ルールに300行の参考情報を加えた規模で再試行。検索なしは検証用185秒上限までに選別完了せず、検索ありは選別セッションがエラーで終了。いずれもC#成果物の比較段階に達していないため、性能・品質に差があるとは判定しない。
- Windows API実送信＋HTTPによる起動の短縮試験では、Run・操作・確認IDが一致し、未回答を保持したまま最終予定時刻を過ぎても新しい再通知送信はなかった。起動時点ですでに送信中だった通知は完了し得る。OSバナーの新1・3・5分の全目視とは区別する。

## 許可・拒否と通知の追試

- #128: ハーネスにACPの合成許可要求を送り、別の下書き・古い要求ID・候補にない回答が拒否されることと、有効な1回限りの許可・拒否がそれぞれ正しいターンに返ることをWindowsで確認。許可後の提案は下書きに留まり、TOMLと元のプロジェクトは変わらない。実Junieでは既にスキル・同一セッション・明示適用を確認済み。今回の実Junieは合成の別ファイルを読まず、ACP許可要求も発行しなかったため、許可要求の発生自体は合成プロトコル試験と区別する。
- #125: 新しい通常間隔で実Windows APIの受理は初回を含む4回。利用者もバナーの表示を確認したが、当該試行のHTTPには開封が届かなかった。通常間隔で開いた後の停止は未確認。短縮試験では開封後・未回答のまま以降の新規送信がないことを確認済み。

## 再現手順

通常のユーザーのPowerShellで、隔離したチェックアウトから実行する。Pythonのほか、対応するNode.jsとEdge/Chromeが必要。

~~~powershell
python -m pip install -e .
python tests/run_shard.py full --require-ui --timings
python tests/smoke_windows_junie.py
python tools/windows_toast_smoke.py --interval 12 --timeout 48
# 開いた後も未回答のまま残し、最終予定時刻を過ぎて再通知がないことを確認
python tools/windows_toast_smoke.py --verify-stop
~~~

通知確認ではブラウザを最小化し、「移行ハーネス」通知をクリックする。合成のRun B画面を開き、スクリプトが一致を出すことを確認。既定間隔の確認は引数なしで開始し、初回・1・3・5分の表示を観察する。途中で通知を開くと、その確認の再通知だけが止まり、未回答の確認がRunに残ることを確認する。「Windows API accepted」は画面に出たことの証明ではない。同じ通知タグが通知センター上では置換されることがある。実画面では、回答後の再通知停止、別Run・別タブ、古い通知、集中モードを使った抑制、通知に本文が含まれないことも記録する。

モデルを使う項目は、Junieで同じWindowsユーザーの利用可能なモデルを確認する。モデル・推論強度・対象コミットを固定し、設定箇所とACPネゴシエーションを記録する。初回と2ターン目について、スキルのコマンド公開と内蔵指示へのフォールバックを区別する。検索比較は比較対象以外を同じにし、必須規則、末尾の例外、優先順位、別画面の除外を独立した静的チェックで採点する。
