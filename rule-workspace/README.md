# 案件ごとのルール整理用フォルダ

散在する移行ルールの固定コピー、分割計画、生成した必須事項と詳細をここに保存します。アプリのリポジトリやRunの `agent-workspace` とは別の、ハーネス側の作業場所です。

```text
rule-workspace/
  LegacyApp/                 # 1つのPACK
    sources/                 # 全入力のコピー。snapshot後は変更しない
      original.md
    sources.json             # snapshotが記録するSHA-256・行数
    plan.json                # 原文を振り分ける行範囲
    generated/               # buildの出力。直接編集しない
      Agent.md               # 毎回適用する必須事項
      details/
        database.md          # 用途別の詳細・例
      coverage.json          # 原文と生成物の対応
      rules.toml             # 絶対パスの設定断片
```

## ダッシュボードで整理する

**ルール整理 → 新しい下書き** で、登録済みルールの原文を確認・編集できます。追加する原文はUTF-8（BOM可）の `.md`、`.markdown`、`.txt` が対象です。他の形式は原ファイルを保持し、変換後の内容を確認して追加してください。

**編集を完了して差分を確認** で、原文の変更と必須／詳細の分類、登録先を確認します。条件・例外・優先順位まで確認できたものだけ **次のRunから適用** を選びます。保存済みのRunや採用済みの生成物は上書きしません。登録済みの生成物は移動・削除せず、必要に応じて別途バックアップしてください。このフォルダ内の案件データはGitの管理対象外です。

## 詳細ルールの読み始めの案内

新しい Run を準備するとき、移行対象の PHP と登録済みルールの版を固定します。対象 PHP の識別子や語を、日本語の語の一部も含めて、固定した参照用の詳細ルールと照合します。識別子の一致を優先し、関数ごとの BM25 の順位で最大 16 件の読み始めの候補を記録します。検索はローカルで行います。新しい Run ごとに固定したルールからメモリ上で計算し、検索索引は保存しません。同じ Run を再開するときは、索引ではなく、その Run に記録した候補を使います。事前操作、追加インストール、追加設定は不要です。

候補なし、検索語なし、一致なし、検索補助の失敗や処理量の上限、保存した候補と詳細資料の不一致、Junie への入力予算不足のときは、案内だけを省きます。案内は採用・除外の根拠ではなく、必須事項の適用も詳細ルール全件の適用判定も変わりません。必須入力のエラーや停止要求は通常どおり処理します。
