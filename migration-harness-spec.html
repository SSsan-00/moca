IMPLEMENTATION STATUS / DESIGN

PHP → C# 移行ハーネス

Windows上でローカル実行するPython + LangGraphのハーネス。移行対象を準備し、指定範囲を分割してJunieに順次渡します。全カプセルの完了後にworktreeでビルドし、成功した場合は設定したチェッカーを実行します。進捗画面のデモも確認できます。

前提

構成と移行先

PythonLangGraphJunie.NET 9

現在、LangGraphが設定検証・コンテキスト作成・worktree作成を管理し、その後PythonからJunie CLIをカプセルごとに順次起動します。JunieはdotUltimateなどで利用するエージェントです。移行先は既存のASP.NET Core Razor Pages（現状.NET 9）で、共通関数などは.csに配置します。

移行材料

  • 元のPHPと、コメントだけを追加した注釈版PHP
  • 別ツールが生成した仮C#
  • 独自移行ルールの該当箇所と必要最小限の既存C#例
  • 差分レビューに使うDiff ViewerワークスペースJSON

大規模コードへの対応

数百万行のリポジトリや数万行のファイルを丸ごとAIへ渡しません。アプリ用worktreeを1つ作り、Junieには対象箇所と必要な参照だけを入れた一時作業フォルダを渡します。

公開する範囲

公開するのは汎用ハーネスと設定例です。独自ルールMarkdown、利用者固有のスクリプト、アプリのソースや設定は利用者側で用意します。

1. 現在の実装フロー

LangGraphとチェックポイント

LangGraphは現在、準備フローを管理します。SQLiteチェックポイントも準備グラフの状態保存に使いますが、保存した状態から再開する機能はまだありません。Junie実行以降は現在LangGraphのグラフ外で動きます。

参照範囲の制限

ハーネスは指定した資料だけをコンテキストにまとめ、Junie用フォルダには対象ファイルとコンテキストだけを置きます。これはハーネス上の範囲指定であり、別の絶対パスへのアクセスをOSレベルで遮断するものではありません。

現在の文字数上限

max_context_charsの既定値は100,000文字です。1回分のコンテキストが上限を超える場合、原文を切り捨てず、現在は行境界で複数カプセルに分割して順にJunieへ渡します。関数や制御構文の境界を判定する機能は未実装です。極端に長い1行は文字位置を記録して分割し、隣接断片の前後512文字（上限の小さい設定では5%）を読み取り用に重ねます。AIにはfocus範囲のみを移行し、重なり範囲は文脈参照に限るよう指示します。文字コード・文字数・元の行範囲・focus範囲・重なり範囲はcapsule/manifest.jsonに記録します。入力はUTF-8 BOMを優先し、BOMなしはUTF-8とEUC-JPを厳密に判定します。両方で異なる文字列になる曖昧な入力や、どちらでも読めない入力は自動選択せず、設定で文字コードを指定します。対象ファイル全体や会話履歴・ツール出力は計上しません。必須の移行ルールと shared = true の入力は毎回同梱し、先に文字数を確保します。原文の改行を保持し、生成するMarkdownの区切りにはLFを使います。

追加インストールを増やさず、ローカルのブラウザーで実行状況を確認します。

進捗の配信

Python標準ライブラリのHTTPサーバーを127.0.0.1で起動し、ブラウザーの標準EventSource APIへSSEで状態とログを送ります。SSEは一方向の配信に使い、WebSocketは使いません。

画面からの操作

モーダルから判断理由の記録と再開をHTTP POSTで送ります。再開時は同じrun IDを使い、Junieはハーネスを起動した端末で対話します。CLIの view で完了済みRunの結果・台帳・差分を開けます。保存済みRunを開いた場合、再開は画面で操作した時点で行います。

再接続と履歴

サーバーは直近100件のイベントに連番IDを付け、再接続時に未受信分を再送します。実行結果と判断理由はrun.jsonに保存します。

公開デモとの違い

公開デモは模擬データで操作を試せます。ハーネスを --dashboard 付きで起動すると、同じ画面で実際の進捗と指摘を確認できます。

台帳の単位（案）

PHPの関数・メソッド・ページ処理など、意味のまとまりを1項目にします。構造を判定できない場合は、設定したファイルと行範囲を使います。行番号だけに頼らず、ファイル・シンボル名・該当範囲を併記します。

状態（案）

未処理、移行候補あり、確認済み、対象外（理由付き）、人の判断待ちを区別します。未処理や判断待ちが残る項目は完了扱いにしません。

依存情報の取得

呼び出し先、include、共通関数、既存C#例、該当ルールを関係情報から探し、必要な原文を追加で渡します。要約は索引として使い、原文の代わりにはしません。

移行先との対応

各入力項目に対して、移行先ファイル・シンボル・範囲と対応の根拠を記録します。チェッカーなどで行番号がずれた場合も、シンボルや内容を合わせて追跡します。

移行完了の判定

PHPの全範囲に確認済みまたは理由付きの対象外の判断があり、現行の移行先でビルドと設定済みチェッカーの条件を満たすと、移行完了を表示します。確認した移行先が変わった範囲は理由を残して要再確認に戻し、同じRun IDで再検証できます。

現在実装した上限超過対応

PHPの全文または明示した行範囲を、上限に応じて行境界で分割し、カプセルを順番にJunieへ渡します。極端に長い1行は文字位置で分割し、各断片のfocus範囲と参照用の重なり範囲をmanifestに残します。比較メニューでJunieがアンカーを生成すると、ハーネスは処理済みのPHP範囲に対応する移行先の候補を割り出し、Run IDごとに保存します。移行台帳では差分と記録済みの判断・理由を閲覧できます。判断はCLIで記録します。移行先の内容が変わった範囲は「要再確認」と表示します。依存情報の追加取得、論理境界での分割、対応の自動検証は今後の設計です。

3. 対話実行の継続と今後の修正ループ

Junieは対話モードで起動し、各カプセルの作業が終わると完了記録を残します。有効な記録を検知すると、ハーネスが対話画面を閉じて次へ進みます。途中で閉じた場合は、保存した編集から再開できます。

Junieの停止と再開

ステップ上限では同じ対話画面で続きを依頼できます。利用枠の回復を待つ場合は、その時点の編集を保存して保留できます。

チェッカーの偽陽性

CLIのreviewで指摘ごとに「問題なし」と判断した理由をrun.jsonに記録できます。同じrun IDで再開するとビルドとチェッカーを実行し、承認済みの指摘だけが残った場合はレビュー済みとして完了します。解釈できないログは人の確認に回します。大きなログでも手動レビューに利用できます。

4. 差分レビューとアンカー連携

進捗ダッシュボード上部の「比較ツールを開く」を押すと、Run作成時の参照PHPとその時点のworktreeの移行先をDiff Viewerで表示し、同じ内容のJSONを自動でダウンロードします。Razorページの右ペインには .cshtml.cs と .cshtml を並べます。targets に両方を明示した場合は、同じRunで両方を編集・ビルド対象にできます。

既存JSONから対応情報を読む

既存のワークスペースJSONを設定ファイルの anchor_reference で指定すると、進捗画面と確認モーダルの比較オプションから「Junieで対応行を提案して開く」を選べます。CLIの anchors からも生成できます。ハーネスは既存アンカーの左右の行を抽出し、対応の例としてJunieに渡します。

Junieがアンカー案を作る

Junieは、準備時に文字コードとハッシュを記録したPHPと、比較時の移行先のコピーを読み、PHPと移行先で同じ処理を担う行の組を提案します。

JSONを検査する

ハーネスはペイン全体の行番号の範囲、重複、順序を検証し、アンカー付きのワークスペースJSONを別ファイルに保存します。

Diff Viewerで人が確認する

画面から生成した場合はDiff Viewerが別タブで開き、同じJSONがダウンロードされます。CLIの場合は表示されたJSONをインポートします。Viewerで提案された対応行を確認し、必要に応じてアンカーを調整します。

Viewerではソースを変更しない

Diff Viewerは保存済みJSONのコピーを表示します。比較画面やJSONを操作しても、PHPやworktreeのソースには書き戻しません。

レビュー後に保存するもの

レビュー済みアンカーJSON、ファイル対応情報、ビルド・テスト結果、チェッカー出力、人が許容した指摘と理由を移行単位ごとに保存します。ソースの差分はアプリ用worktreeから参照し、Viewerから書き戻しません。
