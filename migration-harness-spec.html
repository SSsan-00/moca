IMPLEMENTATION STATUS / DESIGN

MoCA

Migration Orchestrator & Coding Assistant

WindowsでPHPをC#・Razor Pagesへ移行するローカルツールです。サンプルで本番の画面を試す · Windowsで実行する · 技術仕様

前提

構成と移行先

Python 3.11以上Junie CLIGit.NET 9 SDK

C#・Razorの診断と予約語確認には .NET 9 SDK、正式なビルドには移行先アプリが指定するSDKを使います。

移行材料

  • 移行元のPHPと移行先の指定（Razorは .cshtml と .cshtml.cs の組）
  • 必要に応じ、別ツールが生成した仮C#や注釈版PHP
  • 任意の共通ルール・参考実装ペア
  • 任意の差分ビューアーと、アンカーの参考にする既存JSON

大規模コードへの対応

アプリ用worktreeはRunごとに1つ作成します。Junieには対象ファイルと必要な資料を入れた一時作業フォルダを渡します。

公開する範囲

汎用ハーネスと設定例を公開します。アプリのソースや設定、独自ルール、自作スクリプトは利用者が用意します。

実行記録と再開

「実行一覧」の「再開」または「進捗」の「同じ実行を再開」で保存版から続けます。開始工程を選ぶ場合は「再開方法…」で「移行から」「ビルドから」「チェッカーから」を選び、「計画を確認」します。「チェッカーから」は保存済みのビルド成果物を照合できる構成だけです。検証結果を取り直す場合は「再検証」または「ビルド・チェックを再実行」、worktree作成前に停止した場合は新しいRunを使います。

参照範囲の制限

Junie用フォルダの参照起点は、既定では移行先の親フォルダ、その隣のinc、incの一つ上にあるLibs・Extensionsです。通常の再開では作業ツリーの参考ファイルを照合します。変更があれば新版を固定し、既存の成果物を見直します。手修正と競合すれば自動で上書きしません。元PHPは準備時の版を維持し、ビルドやチェッカーからの再開では周辺資料を取り込み直しません。移行先以外は参照専用です。JunieはOSで許可された他のパスにもアクセスできます。

パスの指定

絶対パスと相対パスを指定できます。アプリのリポジトリ・作業ツリーと実行データの保存先・diff_viewer.anchor_reference の相対パスは設定ファイルの場所が基準です。移行元・移行ルール・参考実装・差分ビューアーHTML・仮C#のコピー元はアプリルートが基準で、外部ファイルの絶対パスも読めます。移行元は拡張子なしを含め、拡張子を問わずPHPの入力として扱います。

移行先・ビルド対象・仮C#のコピー先は、アプリルートからの相対パス、またはアプリリポジトリ内の絶対パスに限ります。worktree内のパスに正規化し、元のリポジトリには書き込みません。

移行先はBOM付きUTF-8で保存します。生成物・停止した自動修正の下書きに、新しい予約語エスケープ付き宣言（例 @event）が見つかると、ファイルと行を表示して反映を止めます。通常のRazor構文（例 @if）や既存の宣言、外部APIの参照は一律に拒否しません。

現在の文字数上限

max_context_charsの既定値は1カプセルあたり250,000文字です。ルールは本文と別に全文保存します。必須事項はJunieの起動時の指示に渡し、詳細・例は設定した「読む場面・内容」を基に必要時に原文を読みます。既存ルールの自動要約や除外は行いません。その他の共通入力の分を確保し、原文は行単位（長すぎる行は文字単位）で分割して順にJunieへ渡します。断片の重なりは文脈の参照に使います。共通の参考実装は全文をRunに保存し、Junieが必要な範囲を読みます。

ローカル進捗画面の通信方式

追加インストールを増やさず、ローカルのブラウザーで実行状況を確認します。

moca.cmd でダッシュボードを起動すると、ブラウザーが開きます。「設定」タブで設定を保存し、「実行」タブで「設定を検証」してから実行します。保存済みRunの閲覧・再開も「実行」から行います。「移行先周辺の参照資料」では共通の起点と追加フォルダーを指定できます。移行単位別の設定、除外、再帰収集、容量上限は「TOMLを直接編集」で指定します。ブラウザーからの移行はJunieとACPという通信方式で連携し、操作の許可や追加指示もブラウザーで受け付けます。

同時に最大5件のRunを実行し、残りは実行待ちになります。「進捗」と「エディタ」の「表示する実行」で対象Runを切り替えられます。再起動時は保存済みの実行待ちを継続し、起動済みだったRunは一覧から手動で再開します。「ルール整理」でJunieの終了を確認できない場合は、相談や反映が止まります。「終了を再確認」で終了を確認してから続けます。

「設定 → プロジェクトの詳細設定」でJunieのモデルと推論の強さを選べます。候補はインストール済みJunieから取得し、取得できない場合は代表的な候補を表示します。推論の強さはモデルの対応値から選び、未指定なら既定値を使います。モデルと強さをRunに記録し、移行・ルール確認・自動修正・追加指示・比較アンカー生成・再開に引き継ぎます。既存Runに別の指定を使う場合は、進捗・エディタなどのRunモデル設定で次のJunie起動分を変更します。

「エディタ」では移行元PHPを読み取り、移行先C#・Razorを編集できます。実行中の手修正や追加指示もRunに保存し、画面に表示されたタイミングで反映します。同じ箇所の競合はエディタで解消します。「トークン使用量」ではRunごとの入力・出力とキャッシュの内訳を確認でき、再試行・再開分も集計します。

進捗の配信

SSEで工程の進捗とJunieの実行状況を配信します。プロセスの起動時と稼働中の約3秒ごとに通知します。工程時間はRunに保存し、停止中の待ち時間を除いて加算します。

Windowsの操作確認通知は初回から1・3・5分後に再通知します。通知リンクを開くとその確認だけ再通知を停止しますが、許可・拒否はダッシュボード内で行います。移行完了や停止などの状態通知は操作確認の再通知とは別です。

画面からの操作

実行中は「停止」で編集を保存して止め、同じRunを再開できます。worktree作成前の中断は準備からやり直します。Junieの信頼確認・操作許可は画面のダイアログで受け付けます。手修正への質問にはエディタから追加指示で回答できます。

ACPでモデルを利用できない場合は「今回のみ非対話モードで再試行」を選べます。CLIが対応していれば同じモデル・推論の強さと作業場所で再試行します。非対話モードでは操作ごとの許可確認は表示されません。

再接続と履歴

直近100件のイベントを保持し、再接続時に未受信分を再送します。実行結果と判断理由は run.json に保存します。

公開デモとの違い

公開デモでは本番と同じ画面でサンプルのRunを選び、進捗・移行台帳・エディタを確認できます。操作結果はブラウザー内の模擬データにのみ反映します。実ファイルの読み書き、Junieとの通信、ビルド・チェッカー、Windows通知、ローカルの差分ビューアーとの連携は行いません。実際の移行結果や認証を確認するにはWindowsのローカル版を使います。

2. カプセルの分割と移行台帳

PHPの原文をRunに固定し、カプセルごとに移行範囲と参照範囲を記録します。同じ入力から分割したカプセルには、前後最大12行ずつを参照用に添えます。

繰り返しや定数表は、Junieが元PHPから値と順序を抽出して移行先と照合します。チェッカーが差を検出した場合は、保存済みのカプセルを参照して修正します。

移行台帳ではRunごとにPHPの範囲、処理状態、移行先の対応候補を閲覧できます。

検証結果

全カプセルの処理と現在の版でのビルド・設定済みの検証がそろうと「検証済み」です。照合対象が変わったときは「前回合格・要再検証」となり、「ビルド・チェックを再実行」で確認します。範囲ごとの対応や動作の正しさは別途レビューしてください。

分割と対応候補の範囲

PHPの名前付き関数やメソッドを認識でき、上限内に収まればその境界を保ちます。認識できない箇所や上限を超える箇所は行・文字範囲で分割します。業務の意味が正しく分かれたことを保証するものではありません。アンカー生成時に、処理済みのPHP範囲に対応する移行先の候補をRunに保存します。

3. 中断後の再開と自動修正

ハーネスはカプセルごとの完了記録と対象ファイルを照合します。対話・ACPでは完了後にセッションを終了でき、非対話では自然終了を待ちます。最終区間の手修正と追加指示を処理してからビルドへ進みます。

Junieの停止と再開

ステップ上限で止まった場合は、ダッシュボードから同じRunを再開します。通信失敗が確定すると、同じ作業場所で1秒、3秒の待機を挟んで最大2回再起動します。復旧しない場合は、接続を確認して同じRunを再開します。

ビルドとチェッカーの修正

Junieは準備時のルールと参考実装を使い、C#・Razorのコンパイルエラーやチェッカーの指摘を1 Runにつき既定で2回まで修正します。中断した試行は回数に含めず、再開時に指摘・移行先・停止下書きの版が一致する場合は下書きを引き継ぎます。Junieと子プロセスの終了を確認できない場合は自動で進めません。指摘が厳密に減っている間は設定回数内で続行し、減少しない再発や回数上限で止めて人の確認を待ちます。

自作スクリプトは準備・Junie移行・ビルド・チェッカーの前後に設定順で実行します。準備前はアプリのリポジトリ、それ以降はworktreeで実行します。スクリプトが失敗すると、原則としてその工程のログを保存して停止します。下記の任意設定では、通常の検証中に出力の問題を限定的に修正できます。

標準のチェッカー合格条件は、無出力で終了コード0、または応答全体が「特に気になる点はありません。」だけの場合です。出力はUTF-8を優先し、WindowsのShift-JIS（CP932）にも対応します。成功文の前後の空白・改行・先頭のUTF-8 BOMは許容し、正の終了コードでも受け付けます。起動失敗・中断、JSONや引用に含まれる成功文は合格にしません。それ以外の出力は終了コード0でも確認・修正へ回します。

形式未対応のチェッカー出力や工程スクリプトに対するJunieの参考判定は既定で無効です。参考判定のみでは合否を変えません。別途 [junie].apply_output_decisions = true を有効にすると、終了コード0、出力全体に根拠のある合格判定、ハーネスでも確認できる明示的な成功表現がそろい、ログと対象版が一致する場合だけ続行します。曖昧・不一致なら確認待ちです。通常の検証では、チェッカーまたは after_build の問題を対象内の構造化診断として照合できるときだけ共有の修正枠を使い、修正後はビルドから再検証します。明示的な検証のみの依頼では自動修正しません。

準備前・準備後・移行前の正常終了した設定済みスクリプトは、同じRun・コマンド・ログ・対象版で照合できるソース識別子だけを次の移行に申し送れます。[junie].ground_output_repairs = true を別途有効にすると、通常の検証のチェッカーとビルド前後・チェッカー前後の自由形式の指摘に対し、固定PHPと現行C#の限られた抜粋もモデルに送り、根拠のある対象内の修正だけをビルドから再検証します。既定は無効で、追加の照合にも保存RunのJunieモデル指定を使います。

チェッカーや通常のスクリプトの引数に {worktree}・{build_project}・{target} を使うと、Runの作業場所・ビルド対象・先頭の移行先の絶対パスへ展開します。準備前のスクリプトと仮C#取り込みは対象外です。

チェッカーから再開する・指摘を承認する

「チェッカーから」ではビルドの入力・成果物を照合します。停止した自動修正の下書きは「進捗 → 復旧の確認」で比較して選び直せます。再開方法と保存条件を参照してください。

「進捗」の確認ダイアログで、チェッカーの指摘を理由付きで「問題なしとして記録」できます。同じRunを再開し、承認済みの指摘だけが残ればチェッカーの条件を満たします。解釈できないログは人が確認します。

4. 差分レビューとアンカー連携

「比較ツールを開く」で、準備時のPHPと最新の移行先を比較します。Junieの実行中は保存済みの編集中ファイルを表示し、取得時点のJSONを保存します。比較画面は移行処理に影響しません。

差分ビューアーと対応例の設定

設定で差分ビューアーを有効にし、HTMLを指定します。HTMLが空欄、または「使用しない」なら比較とアンカー生成は無効です。進捗画面や確認モーダルから「Junieで対応行を提案して開く」を選べます。「アンカーの参照JSON（任意）」にパスを1行に1つ指定すると、各ワークスペースJSONから対応例を読み込みます。空欄なら手本なしで今回の比較から提案します。指定ファイルがない・JSONが不正な場合はエラーになります。

Junieがアンカー案を作る

Junieは準備時のPHPと現在の移行先のコピーから、同じ処理を担う行の組を提案します。

JSONを検査する

行番号の範囲・重複・順序を検証し、アンカー付きJSONを別ファイルに保存します。

Diff Viewerで人が確認する

Diff Viewerを別タブで開き、取得時点のスナップショットを確認します。JSONが必要な場合は進捗画面の「ワークスペースJSONを保存」からダウンロードします。対応行を確認し、必要に応じてアンカーを調整します。

Viewerではソースを変更しない

Diff Viewerで変更できるのはワークスペースJSON内のデータです。

レビュー後に保存するもの

移行単位ごとに、レビュー済みアンカーJSON、ファイル対応、ビルド・テスト結果、チェッカー出力、承認した指摘と理由を保存します。ソースの差分はworktreeで確認できます。
